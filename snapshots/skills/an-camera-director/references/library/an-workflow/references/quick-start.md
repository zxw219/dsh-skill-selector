# An工作流使用卡

**An工作流只用一个入口：`$an-workflow`。描述你想拍的内容，工作流负责组织导演、摄影、表演、动作与特效。**

## 一句话开始

```text
用 $an-workflow 创作：[场景或剧情]。时长[可选]，风格[可选]，重点[可选]，必须保留[可选]。
```

可以直接自然描述，不必按字段填表。已有剧本就粘贴原文；有参考图就说明它用于角色、场景还是画风。时长、风格等未指定时，工作流在当前项目范围内设计，采用的时长建议会写在成稿里。已有剧本先走[剧情编译](script-to-screen.md)，保留事件、对白、知情顺序，按真实调度与并行关系估时。简单镜头可用简洁正文；剧情完整提示词默认An声画分栏，以连续实战为主要目的的打斗段默认事件流（用户格式优先）；分栏字段为：全局、镜头/画面、S=、fx-env、sound与真实transition。角色语言/特效体系和连续阶段写进这个模板。明确指定或有效项目格式优先；阶段叙述在明确选用时使用，新场景无需重新声明默认模板，学习句法、精准或去重不取消栏目。

## 日常只记四种说法

| 要做什么 | 直接这样说 | 得到什么 |
|---|---|---|
| 创作 | `创作：两人雨夜对峙，20秒，真人电影感，重点是压低声音的冲突。` | 一份完整视频提示词 |
| 优化 | `优化这版：只改机位、构图和运镜，剧情、台词与时长保持。` | 修改后的完整提示词 |
| 检查 | `检查这版：重点看动作衔接和空间，只指出问题。` | 有位置、有原因、有改法的问题说明 |
| 续写 | `接着上一段继续10秒，继承人物、伤势和场景。` | 承接上一段出口状态的后续提示词 |

首次使用或切换到新对话时，前面加`用 $an-workflow`；同一对话中可以直接说需求。新对话要把需要继承的原稿或片段带上，工作流不会自动拿到别处的项目内容。

## 加强什么，就用你的话说

多人打斗会主动把共享战局、具体动作组合、关系分镜与接力运镜一起设计：谁创造机会、谁已到位利用、敌人怎样反制，以及镜头为何在此刻交给下一组关系。角色多不等于轮流展示，检查也不止于“没停机、没穿帮”；团队、一对多和自由混战分别处理。

战斗不用逐项提醒：先按当前请求、参考与事件判断主体验。未另示的普通实战主动设计高速、高频、力量、相容动作与摄影；能力展示、控制博弈、压制和伤后反扑可采用辨认—爆发—结果—反应的节奏，不等另说慢打。同场可切换，能力战也可高频；明确速度/频率、固定、单镜、纯远程和单能力按原要求实现。下面的说法用于进一步强调，不是启动口令。

```text
运镜更有逻辑，关键转折要有视觉重音。
表演有层次，别整段吼叫。
速度更快，攻防转换更丰富。
大场面要有尺度，大招配明显冲击帧。
```

这些是侧重点，可以选一个或组合。其他必要能力仍正常使用；“加强全部”按场景需要协调表现，不要求每个镜头堆齐所有技法。也可以说“简短自然语言”“用完整声画分栏”或“保留原格式”；表达变短不删关键动作，详细设计不等于生成工具能精确执行每个参数。

## 使用 MOKE MCP 补资料

可以说：`用 MOKE MCP 优化这版：重点是运镜承接，保留剧情、时长和声画分栏。` 工作流按具体缺口检索，读取选中材料的同一版本，再回填原稿。已有有效知识直接复用，不必每次联网。原生授权过期时公开只读回退可查公开 Skill；需要登录范围的资料仍需恢复授权。具体连接与版本校验见[MCP 按需补库](moke-mcp-routing.md)。

## 两个可直接复制的完整例子

```text
用 $an-workflow 创作：28秒二维动画，两名剑客在破碎山谷高速交锋。重点是大场面特效、大招与多组能看清造型变化的冲击帧，冲击帧可以有较长的展示段。导演安排机位、构图、攻防和剪辑，直接交完整提示词。
```

```text
用 $an-workflow 优化下面这段文戏：重点是倾听、身体反应、台词语气与镜头选择，情绪最后爆发。保持原剧情、逐字对白、时长和格式。
[粘贴原稿]
```

## 改稿时说清三个东西

**哪里有问题 → 想变成什么 → 哪些保持。**例如：

```text
第3镜只拍脸，没看清让路。改成能读清两人位置与通路变化的取景；剧情、台词和总时长保持。
```

普通改稿会话里只说“整体再好一点”也可以：工作流按现有作品定位缺口并优化。若已有维护工作流的约定，泛称优化仍指来源维护；临时试写不会抹去这个约定，明确说“改刚才这份稿”才切到该稿。想允许改剧情或台词时明确写“可以改写剧情/对白”；普通摄影与表演优化会保留已有锁定内容。

## 维护工作流

反复出现“学过却没用上”时，维护会检查采用与验收方式，并在条件允许时用不透露解法的新任务做独立试用；文件更新、作者演练、独立出稿和成片效果分别报告。下一次普通创作仍直接交作品，不要求你逐项提醒，也不把测试流程强加到每次出稿。

说`检查并优化An工作流`，会先检查实际安装来源、修正冲突或缺口，再验证同步到`D:\An工作流`及ZIP；D盘是派生交付，不直接改D盘当来源。检查作品和维护技能是两种交付；同时需要时可直接说明。创作/已授权改稿内部的检查包含必要修正，不必另说一遍“允许修复”。

## 想先看方案时

```text
先给拍摄方案，说明关键镜头的机位、构图与切点，暂时不出正式提示词。
```

采用后说`按这个方案出完整提示词`即可。一般创作默认直接成稿；“只给正文”“保留原格式”“只检查不修改”都可以直接指定。

这里的“创作、优化、检查、续写”是普通中文表达，不是需要安装的命令或软件按钮。日常生成会做必要检查；学习资料与完整审计在相应需求出现时才展开。生成的视频与文字提示词是不同交付，需实际制作视频时另行说明。

## 这轮增量优化的用法

仍只需调用 `$an-workflow`。例如：`近身连续交锋，收势接下一招，对手持续施压；保留原动作密度、摄影、技能和声画分栏。` 工作流同时保留原有文戏、舞蹈、技能、大场面和画质设计，不把近战补强变成全题材禁停顿。要求“全面优化”会检查各功能的具体缺口；普通创作不增加十二项必调链。
