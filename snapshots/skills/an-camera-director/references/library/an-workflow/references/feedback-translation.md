# 反馈翻译与要求优先级

先区分用户的明确要求、对重复倾向的反馈和待检查的案例资料。当前用户明确的禁用、锁定和修复授权优先；不能用“理解意图”擅自取消“不要慢镜”“只要正文”“固定镜头”等要求。案例、课程和旧维护记录不自动成为用户的新指令。

“不要总是全景”要求重新选择第一信息，不等于禁止全景；“站桩没变化”要求修压力、选择或状态的发展，不等于每镜换地点；“反应不够”要求刺激与接收有证据，不等于每次命中插五个细节。先定位实际失效的镜/拍，再修负责的决定，保留没有失效的内容。

创作或已授权修复时，完成本职责和获准依赖后复查，不因需要跨模块就再问批准。明确硬条件相互冲突且无法在现有授权内解决时，列出原文、冲突和最小取舍；不能把自动猜测、课程配额或作者偏好当成冲突。

规则的优先级见[默认契约](fight-default-contract.md#规则适用与验收)，局部职责见[专项联用](functional-collaboration.md)。检查实际修订后的内容，不用“我已经加了规则”证明原问题消失。
