# 2026-10-16：战斗主动执行失效与维护核对

证据来自同一会话的两张角色图、两版30秒提示词与用户反馈；未生成或观看对应成片，本记录不报告模型行为测试或成片改善。

## 原稿暴露的问题

- 用户只说“为这两个角色设计一段30秒的打斗提示词”，随后要求“检查一下优化后发给我”。助手主要读角色施法、时间与关系覆盖，未将已有动作模块、速度/力量和动态摄影主动编进足够丰富的攻防；路由把不少学习内容挂在“用户要求/反馈不足”之后，必要选用未发生。
- 优化稿8.1–11.7秒主要为一次地面攻击、托举、落地准备；16.2–20.4秒主要为一次引偏、碎石推送和雷幕接住；20.4–25.6秒仍以推幕、挤窄、改楔、撑裂为主。并非绝无动作，但短促交锋的连续接力不足，法术形状变化被当成模组丰富。
- 多镜采用东侧跟拍、小幅退移、略升高和再拉开；文字确实包含相机移动，不能说完全零运镜，但起落幅的压力、相对速度与阅读变化不足，未兑现用户所要的张力。
- 终段25.6–30.0秒包含制住、看手、抬眼、熄雷、收火、松手和呼吸。胜负已明后仍用较长时间逐项收尾，挤占快战。轻灵角色、柔和画风也被过度写成短幅度推挡，普通招的传力和受力证据偏弱。
- 上次检查重点是南北站位、断索供能和受伤手资源。修这些有必要，但只修连续性不能声称整体体验已优化。

## 来源修复

入口把普通打斗主动默认前置；体验设计先编交锋簇再分秒数，分别检查速度、有效频率、力量和停顿；动作库在选招阶段启用；施法以相容并行与改控接力；摄影写事件触发的相对运动与观看交接；终检先查体验证据，修连续性后仍回查体验。使用卡、手册及提取功能映射保持同一边界。没有新增统一招数、切镜次数或所有任务强制移动镜头的配额。

## 人工情境审阅

以下是维护者按修订规则做的文字推演，不是独立模型实测；不生成新版用户作品。

| 输入情境 | 检查出的首个职责与适用边界 |
|---|---|
| 两张角色图＋“设计30秒打斗”，未说高速或运镜 | 创作；先补相容战法并编交锋簇，主动设计快战、力量、模块和摄影，再编时轴；造型不锁定只有一类技能 |
| 在该稿后说“检查优化后发给我” | 已授权作品修订；先检验既定体验，不能只纠位置与时码；此表不授权本次维护另交作品 |
| “动作慢、软、模组少、镜头弱，优化工作流” | 来源维护；定位触发/选用/表达/验收失效，修改实际来源及同步，不能交一份改写提示词代替 |
| “固定镜头，一镜到底，单一法术高速交锋” | 保留固定、单镜和单能力，用作用/操作/攻防条件变化、画内纵深与接力兑现快战，不新增运镜或能力 |
| “慢速教学拆招”或“仪式对峙，停顿有压迫” | 明确节奏优先，保留分解、保持和阅读；力量与观看仍服务当前目的，不硬加连击 |
| “只改摄影，动作剧情不动” | 摄影职责内选择取景/路径/相对速度，动作缺口交证据，不擅自加攻或换结局 |
| “安静文戏，单机位” | 不启用快战默认，按人物任务和表演设计 |

## 重新审看失败片段

按新门槛，旧稿中较长托举/准备与持续推幕段不能凭“始终在运动”放行；去掉技能名后大量推面操作不能直接算丰富；去掉镜头名称后等大同侧跟随须回修；最终熄雷/松手段要核必要占时。空间和手部正确不改变这些结论。
