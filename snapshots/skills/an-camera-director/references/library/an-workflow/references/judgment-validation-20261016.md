# 判断与验收改进：2026-10-16 验证记录

本轮维护针对“已经读过知识，出稿仍未采用；作者检查放行后仍需用户逐项指出”的重复问题。修改已进入工作流来源；本记录不是稳定能力保证，也不是默认剧情模板。

## 实际修改

- 入口和导演推敲：先确定不可改事实与决定体验的关键选择，再读能改变选择的知识；采用结果须出现在事件、人物关系和观看过程里。
- 成稿检查：从最弱关键段找反证，不能借作者意图补全正文；比较同条件替代后修实际内容，不用速度、力量或电影感标签放行。
- 维护流程：冻结旧版和新任务，隔离创作者与修复提示，匿名审阅实际成品；分别登记文件一致性、作者检查、独立文本验证和真实成片证据。
- 场景导演、提示词编译、质量审阅三个功能入口同步上述职责内的改变。保留其他功能范围、用户锁定条件和旧有扩展规则；普通创作不强制多代理或测试报告。

## 试用方法与原始证据

任务和评价范围在有效成稿前冻结，见[试用规格](../assets/validation/judgment-20261016/trial-spec.md)。主任务为18秒倾斜货船上四人夺匣，旧版和新版接收同一任务，各自读取技能；创作者未得到缺陷诊断、预期解法或审阅反馈。旧版已经包含前两轮速度、力量、多人因果与运镜修订，本次比较的是新增判断和验收方法。

独立审阅只接收原任务、质量目标和匿名稿，未获得版本身份。A为新版，B为旧版；审阅完成后对照[版本映射](../assets/validation/judgment-20261016/version-map.json)。另外独立试写12秒三方互敌的钟楼夺钥匙任务，并检查慢速固定教学、仅改摄影的单能力远程战、维护后临时试写再继续优化三项边界。首次试用被传输/会话中断且无成稿，不计质量结果。

原件保留： [新版稿](../assets/validation/judgment-20261016/candidate.txt)、[旧版稿](../assets/validation/judgment-20261016/baseline.txt)、[匿名审阅](../assets/validation/judgment-20261016/review.txt)、[迁移稿](../assets/validation/judgment-20261016/transfer.txt)、[边界回答](../assets/validation/judgment-20261016/boundary.txt)、[迁移与边界审阅](../assets/validation/judgment-20261016/transfer-review.txt)。阅读记录、匿名副本、版本指纹与原件SHA-256一并存档，见[证据清单](../assets/validation/judgment-20261016/evidence-manifest.json)。所有原始文本保持未修订。

## 实际结果

独立审阅判定两份主稿在文本层面可交付，未指定整体优胜。新版的武器交锋转换、援护后立即发生反制更连贯；旧版的匣体状态、控制条件与双手承重交代更充分。此结果不能证明新增规则导致稳定提升。

新版最弱段为8.0—10.0秒：链镰脱钩、回收再投的剩余链长及回收终点欠清楚；14.5秒后接回镰柄也可更明确。旧版最弱段为3.8—4.5秒：链条擦碰棍身如何形成牵拉约束欠写。这些是独立审阅保留的局部风险，未被认定为确定的能力矛盾或必然无法执行。不得把这些原稿改好后冒称首次无提示输出。

三方互敌迁移稿在文本层面可交付：争夺关系、施术手资源、能力距离、钥匙交接和摄影观看线索有证据；6.5—8.3秒手与钥匙惯性落弧交点仍可具体化。三项边界回答均保留了用户约束和当前维护对象。

## 证据边界与后续采用

本轮完成的是一组旧新对照、一个新场景迁移及三项边界的独立文本验证。样本少、输出有随机性、审阅有判断差异；无生成视频，也未进行正常速度观看。不能据此宣称已经解决速度、力量、多人调度或镜头张力的实际成片问题，不能宣称稳定优于旧版。

本轮保留判断与反证机制及上述限制，不因单例局部欠写继续堆一条链镰专属禁令。后续实际任务检验能否自主发现并处理同类空间/资源交接；若反复漏用，按维护流程定位来源再修。文件、链接与ZIP验证只证明交付一致性，和上述创作结论分别报告。
