# 检查与标准例

文件测试时使用检查器。普通写稿可以参考下面的表达粒度，不自动生成契约文件或运行脚本。保留用户已选模板，检查格式不反向强制改变用户对白。

下面命令从当前技能目录执行：主工作流与提取功能包均提供 `scripts/check_prompt.py`。功能包该入口转交包内参考库中的同版检查器，移动或单独解压后仍可运行；不在技能目录时使用该入口的绝对路径。提示词与契约文件路径按实际位置提供，普通创作不因此自动运行检查。

## 检查模式与时间含义

动作/打斗默认按[小数秒编排](subsecond-action-timing.md)写0.1秒精度的设计时间。现有检查器支持如`S=0.0–0.4s`和小数镜头包络，检测主时间轴的缺口、重叠、反向、越界及终点不符；不自动强制旧稿改精度。段内`t=0.3s`默认仍提示人工复核；明确采用全片绝对锚点的文件可加`--event-times absolute`核数值范围及行动段内顺序。动作可达性、相位理解与成片执行不在数值检查范围。

```text
python scripts/check_prompt.py prompt.txt --profile fusion --start 20 --end 30 --event-times absolute
python scripts/check_prompt.py prompt.txt --profile fusion --end 16 --contract contract.json
```

`--start`为本次正文的全片绝对起点，默认0；`--end`为绝对终点，不是片段长度。20–30秒的长度为10秒。旧`--duration`保留为绝对终点别名，与`--end`同时提供必须相等；不能把10传成20–30秒的终点。

| 模式 | 覆盖 |
|---|---|
| basic（命令与旧API默认） | 文本卫生、已支持素材标签与可解析区间；不要求融合模板 |
| fusion（声画分栏稿的文件检查应显式选择） | basic加全局、镜头、画面、各S段非空fx-env/sound、各镜末段transition |
| compact | 基础时间与卫生检查；默认t=节点提示人工复核，可显式启用绝对数值检查，不强制融合栏位 |
| prose | 按入口规则选择简洁正文或用户指定自然叙述时使用；不因没有S时间轴报错，仍检查文本卫生与显式区间 |

CLI无时间轴且不是prose时提示复核。函数`check_text`的basic默认保留短文本卫生检查兼容性；需要声画分栏模板验收时传`profile='fusion'`。空文件在所有模式中都是输入错误，不用无内容PASS表示成功。

模式由原请求及实际选用格式决定，不由“想让检查通过”决定。简洁自然叙述不强制补An标题；已采用An分栏则核镜头头部、S和逐段栏目。总S内用t节点，多个S则逐段挂栏目，避免总S加裸子区间被当成重复主时间线。语义审阅无硬错不代表这层格式检查也已通过。

退出码0表示未检出硬错误，1表示检出硬错误，2表示输入/参数错误。必须同时读取`status`和各项`*_validation`：`RUN`仅表示已运行，`NOT_RUN`表示未覆盖；`TEXT_REVIEW_REQUIRED`还有待人工处理项。即使`TEXT_CHECK_PASS`，语义与成片也没有自动验收。

旧`--reference @图片1`、`--allow-platform-params`与`--geometry`保留。几何只验证显式二维坐标，不能重建自然语言或成片中的三维空间。

## 显式绝对事件锚点（可选）

`--event-times absolute` / API `event_times='absolute'`只适用于以全片绝对时间编写的显式S正文。检查普通数字`t=`是否在所属S范围内、行动段中是否按非递减顺序书写；同一时刻可并行，段边界允许等于起/止点。续写20–21秒中的`t=0.4s`会报越界，不擅自换算相对时间。

fx-env/sound中的`t=`也核所属段范围，但不与行动段比较书写顺序，允许回指同次接触；台词/引文引号内的`t=`不当作执行节点。近似`t≈`、非数字`t=`或不归属S的数值节点给人工复核项。数值节点范围错误为`EVENT_TIME_RANGE`，行动书写回退为`EVENT_TIME_ORDER`；引用/倒叙或相对时间仍用默认review模式，不为迎合工具改正文。

输出`event_time_validation=ABSOLUTE_NUMERIC_ONLY`表示运行过显式数值检查，不保证动作可达、声画因果或逐帧执行；默认模式或没有未被引号包住的数值锚点时为`NOT_RUN`。仍须结合`status/findings`，不能仅凭覆盖字段放行。数值回归与对白/静音/叠化测试可运行`scripts/test_prompt_contracts.py`。

## 显式二维空间数据（可选）

位置/方向故障的设计方法见[空间连续推演](spatial-continuity.md)。有可靠采用布局时才给`--geometry geometry.json`，统一坐标`[向东,向北]`、距离单位与时间单位。该文件是待核证据，不由待验结论反推一份必能通过的地图；普通出稿不自动创建。

除原有`projections`、`routes`、`axes`外，支持：

- `distances`：`a/b`为同一相位的两点，至少给`min/max/claimed`之一；`tolerance`默认为1e-6，代表显式距离约束允许的数值误差，单位同坐标。
- `motions`：`from/to`为角色平面起终点。`facing`为本直段期间不变的正前向量，`direction`可为`forward/backward/lateral`，分别检查正前、正后、严格垂直的位移分量；真实转身或弧线须在关键相位拆分，不把整个复合动作硬套一个方向。`target_from/target_to`为同期目标起终点，省略`target_to`表示目标不动；`distance_change`的`closer/farther/unchanged`另核双方新旧距离，身体后撤不自动等于增距。可给`duration/max_speed`核最短平面行程是否已经超过本场明确采用的速度预算，不强设人体速度上限，也不模拟弧线路程、跃迁或落地。
- `dynamic_axes`：`frames`中每项给当时的`a/b/camera`，至少两个状态；A/B按固定身份排列、采用同一种已建立轴。符号反转而无`bridge`时报告`DYNAMIC_AXIS_CROSSING`；`bridge`沿用`visible_crossing/neutral_shot/reestablish`。桥接字段只是声明，仍须核真实正文/成片证据；轴上采样本身不证明拍过中性镜。端点重合时该轴无定义，需改用已采用的行动轴或重新建立。

以下是用于诊断的假设数据，不是给既有作品补定坐标；第一项后退却声称接近，第二项固定机位因人物绕行出现动态轴换侧，两者应检出错误：

```json
{
  "motions": [{
    "from": [2, 4], "to": [2, 2], "facing": [0, 1], "direction": "backward",
    "target_from": [0, 8], "distance_change": "closer"
  }],
  "dynamic_axes": [{"frames": [
    {"a": [0, 0], "b": [0, 4], "camera": [3, 2]},
    {"a": [8, 0], "b": [0, 4], "camera": [3, 2]}
  ]}]
}
```

`DISTANCE_MISMATCH/MOTION_DIRECTION/DISTANCE_CHANGE/MOTION_BUDGET`分别表示显式距值、固定朝向直段方向、距变与最短行程预算不符。检查不会读懂提示词、重建高度/体积、证明中间所有状态无碰撞，或验证可达视场。二维路线相交不能判定一次已建立高跳一定碰墙；动态采样通过也不能证明整段轴线没穿越。输入数据错误返回2，已检出的声明矛盾返回1，其余仍按语义/成片范围核验。

维护数值分支时可运行`scripts/test_spatial_geometry.py`，包含故障和合法相邻反例；它证明显式数据检查的行为，不是独立模型试写或成片验收。

第二轮输入检查见`scripts/test_deep_regressions.py`：同一字段大小写不影响空动作判定；默认t复核支持中文紧邻。契约/几何JSON的重复键和非有限常量拒绝为输入错误，超出数值计算范围也保持JSON错误与退出2。明确sound对白中的字面模板/参数/素材字符不作为实际指令；视觉与音乐中的真实引用仍需绑定，原词契约照常逐字核对。该豁免只覆盖文档化的单行引号对白，不宣称读懂任意引文。

显式几何对象及障碍只接受已列字段，拼错`screen/obstacles/bridge`等字段属于输入错误，退出2；不能静默忽略后报告通过。维护回归`scripts/test_audit_regressions.py`另核几何字段、发布前手动改动保护与外部MCP资料格式/哈希（离线桩，不连接服务）。这些测试在主工作流源运行，不宣称每个独立功能包都提供整套维护工具。

## 对白与静音契约

契约只在文件验证需要时创建，不输出进视频提示词。`dialogue`来自用户锁定原文，不能从待验稿反向生成，否则无法发现漏词。

```json
{
  "dialogue": [
    {"speaker": "甲", "text": "我以为你会留下，可你连告别都没有。"},
    {"speaker": "乙", "text": "我留下，你就会放过他吗？"}
  ],
  "sound_mode": "unspecified"
}
```

待验稿每条对白放在sound一行内，使用中文双引号或英文双引号，每段引号前重新标说话人，例如：

```text
sound：甲，画内对白：“我以为你会留下，”
sound：甲，同场画外对白：“可你连告别都没有。”
sound：乙，画内对白：“我留下，你就会放过他吗？”
```

这三行实际分别属于各自S段，不是同一S段重复sound。多说话人在同段时也各自标明，例如`甲，画内：“先走。” 乙，同场画外：“好。”`。对白时间顺序以sound内的书写顺序为准；跨镜同一说话人的片段会拼接，连标点和空格逐字比较，角色归属也参与比对。语气标注放引号外。嵌套引号、含引用的环境声、复杂重叠对白等超出简易语法时，报告未解析/需复核，不改写原词迎合工具。

静音契约用`{"sound_mode":"silent","dialogue":[]}`。最简可验sound是“完全静音”“静音”或“无声”；额外声音描述要求复核，明确有引号内发声则违反静音。完全静音与非空锁定对白属于契约输入冲突。没有原对白契约时不声称已逐字验证；其他声音模式按用户原要求人工核对。

## 叠化：画面包络与主时间线分开

镜头1画面存在于0–3秒，镜头2存在于2–5秒；2–3秒叠化，最终片长5秒。前镜末尾明确写`transition：叠化 S=2–3s；镜头1→镜头2`。主时间线的重叠段只写在前镜一次，后镜正文从叠化完成后的3秒继续；两侧画面在重叠期间如何变化写在那一个S段内。

```text
【全局设定与核心铁律】
5秒，16:9，真人电影；室内柔光，完全静音。前镜为甲握钥匙的手部，后镜为乙握同一钥匙的手部；叠化表示时间跳跃，不是钥匙穿手或人物变身。
【镜头组织：两个镜头，2–3秒叠化】
【镜头1：S=0–3s｜固定手部近景】
画面：甲的右手位于中央，握住钥匙；锁定钥匙朝向和接触位置。
S=0–2s：甲收拢手指，握稳钥匙。
fx-env：钥匙接受室内柔光。
sound：完全静音。
S=2–3s：甲握持画面逐渐淡去；乙已握住钥匙的匹配近景从此刻叠入，两幅画面在1秒内交换可见度。
fx-env：重叠仅来自剪辑，钥匙和手没有实体透明化。
sound：完全静音。
transition：叠化 S=2–3s；镜头1→镜头2。
【镜头2：S=2–5s｜固定手部近景】
画面：乙右手保持匹配握姿；2–3秒的叠入已在上一S段描述。
S=3–5s：叠化完成，乙握钥匙的手落向腿侧。
fx-env：乙与钥匙保持实体和正常受光。
sound：完全静音。
transition：动作完成后直接结束。
```

只对符合声明的相邻两镜放行重叠，声明放在前镜最后一个S段的transition中，明确现有镜号或写“前镜→后镜”。镜号不重复，目标不能指向缺失或非相邻镜头；意外重复S、缺口、叠化越界仍报错。不支持多层叠化或后镜在重叠结束前再次切出的复杂编辑结构时，应明确人工复核，不伪装成普通连续S稿。无时码的黑场/字幕卡标题按其所属正文S段推导包络；有时码则与正文核对。fusion中的黑场画面栏写“纯黑”，无需摄影参数。

## 指定声画分栏时的完整短例

以下用于已指定或沿用An分栏的简单场景，只校准表达粒度，不迁移人物、道具和固定时长。无既定格式的简单镜头可按入口页使用简洁正文，并选择prose检查。

```text
【全局设定与核心铁律】
二维线描，6秒，16:9；简洁室内桌前，仅甲乙相对坐着。甲在左，乙在右；钥匙在甲手边。固定略俯视双人中景，桌面及双方操作手清楚；完全静音。
【镜头组织：一镜到底】
【镜头：S=0–6s｜固定双人中景，观看钥匙控制权交接】
画面：交接区位于中央，甲用左手推钥匙齿端，乙自身右手可接触钥匙头，两手不互相遮挡。
S=0–3s：甲沿桌面把钥匙推向乙；乙右手握稳钥匙头后，甲才松手并撤回。
fx-env：钥匙连续滑动后停住，轮廓不变。
sound：完全静音。
S=3–6s：乙右手把钥匙收至身前，甲左手已离开；两人保持坐姿。
fx-env：桌面和光照延续。
sound：完全静音。
transition：收回完成时直接结束。
```

复杂场景可增加有职责的镜头/事件段，保留同样的全局—画面—变化分工。压缩时删除同义复述，不删原词、接触阶段、观看重点、声音范围或指定强度。不以本例的长度要求所有场景，也不为“更短”合并必须分别读清的事件。

## 思考、文字和成片证据分开

结构检查不测导演判断、美感、修仙战术或跨镜真实节奏。维护时核[最新学习](latest-combat-study-20261010.md)的路由、实际执行方法、案例时间/栏目与源/分发/ZIP一致，再人工审阅采用的角色机制和信息关系；未生成不能报成片优化已验证。普通写稿仍按入口完成语义复核，不因加入思考强制跑脚本。
