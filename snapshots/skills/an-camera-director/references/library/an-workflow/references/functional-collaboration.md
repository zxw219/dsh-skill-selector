# 专项联用：先限定修改，再核对承接

用于“只改摄影/声音/表演/编译”等局部返工，及独立调用提取功能技能。主工作流全面创作仍统筹必要决定；本页不把所有请求改成局部修订。

## 三种信息分别处理

- **继承事实**：用户或已采用上游给出的角色、能力、行动、结果、素材、时长、声音和格式。可读取以理解本职责，不因读到跨板块知识获得改写权限。
- **本职责可改项**：在当前授权范围选择并回填实际句子。改取景、路径、触发或表达时，沿同一次事件验证仍看得到原行动与结果；无需重写整场或重新取全库。
- **依赖冲突**：如原行动在空间上不可达、锁定对白与完全静音相冲突，或规定一镜到底却要求真实切镜。先尝试本职责内可成立的处理；仍无解则给原文位置、冲突条件和最小改法。已有授权包含该依赖时直接修；必须改变未获准的锁定事实才请求取舍。不要把建议写成已发生的新事实。

## 跨板块规则如何生效

提取入口的角色战法、动作、规模、成年魅力、快战、舞蹈及平台规则只在本段实际涉及该内容时使用。摄影读取既定能力以选择可见位置，不负责创作新能力；声音读取接触相位以配声，不改变命中；平台适配保留已有镜头和动作，不重新导演。依赖库完整是为了可独立安装，不代表每次全读或调用全部功能。

| 局部请求 | 本职责内的实际处理 | 上游问题的处理 |
|---|---|---|
| 横移改为追逐跟拍 | 在原人物路线旁选可达跟随路线，定起幅、相对速度、转向触发和落幅；保留原追逐结果 | 原路线穿墙先指出具体位置，不补瞬移解决 |
| 手诀在全景看不清 | 构图/摄影改占幅、角度或遮挡；保持同次发动和控制相位 | 声音/平台功能只标出覆盖缺口，不自行加特写或改镜数 |
| 加强接触声音 | 对已有接触、受力和余响分主次，遵守声音范围与原词 | 原文没有命中证据时不靠音效宣布命中；完全静音时保留静音 |
| 施法者反应呆滞 | 表演处理已有刺激接收、视线、呼吸和相容身体任务 | 不给持续控法的手新增互斥动作，不替换角色战法 |
| 适配明确的Seedance 2.5 | 一次编译真实标签、引用职责和语法，继承时长、动作与声画格式 | 未明确版本不替用户选2.5；能力冲突报告上游，不新增技能或拆段 |

## 局部交付与复核

### 构图与运镜共用同一镜头

构图负责观看对象、覆盖范围、主次与切点意图；运镜负责相机如何从起幅经关键中段到达落幅。二者共享同一份镜头方案，不各自另交全场稿。当前任务授权优化摄影时，取景、机位、焦点、可达路径与触发可共同调整，沿同一事件检查起中落幅、遮挡、轴线和接出；不能将一次必要调整反复退给对方。仅改运镜或仅改构图时先守当前局部授权，确需改变另一侧的锁定条件则给具体冲突和最小改法；已有授权包含该依赖时直接合并修复。

其他模块提出的是证据需求，例如“此刻要辨认控制手是否松开”，不自行指定新特写或切镜。原动作条件不存在时先修获准事件；覆盖缺口才修观察。多处相容修订合并回原镜头后复查受影响后镜，不为模块分工新增用户审批或固定往返轮数。

按用户需要交可直接替换的段落，或把获准修订并回完整稿；“完整稿”是便于复制的交付形式，不扩大修改范围。记录实际改动及受影响承接，复核这些依赖；仅改摄影时不宣称全场动作、对白或成片都已验证。完整创作/全面改稿仍做全部适用的语义复核。

工作流维护修改负责的安装来源和功能定义，验证后按[维护规则](bundle-maintenance.md)同步；不直接修改派生入口，也不交样本新版代替修规则。
