# Seedance 提示词生成器

**语言规则：用户用什么语言提问，就用什么语言回复。**

## Seedance 2.5 专项分支（先于下方独立流程）

目标明确为 Seedance 2.5 / SD2.5 / Dreamina 2.5 时，读取 [seedance-2-5-prompting](../seedance-2-5-prompting/entry-guide.md)，只传递现有正文、锁定事实、真实素材职责及当前模板，由该模块完成一次平台适配与精准成稿；本技能不继续运行下方独立创作、类型模板或第二次编译。它不反向调用本入口，避免循环。已读取且有效的平台配置复用，具体编辑/延长/关键帧/白模参考按任务加载。

泛称即梦、Seedance或单说30秒不自动触发2.5。当前版本缺失但不影响交稿时保持平台中立；确实影响可执行模式时才确认。2.0继续按下方对应分支。2.5保留明确时长、用户模板与已有时间码，不把“阶段”当禁用时间码，不把引用标签空格当版本分界。

## 总工作流编译模式

由 `$an-scene-workflow`、`$an-workflow`、`$ai-video-pipeline` 或 `$anime-video-prompt-workflow` 调用，或用户同时点名其中一个场景工作流与本技能时，进入平台编译模式。以用户实际点名的场景工作流为上游，不自动改走另一个。本技能是最后的平台编译器，不是第二个创作系统：

- 完整继承已批准的主体、剧情顺序、动作链、镜头、表演、特效、声音、结尾和禁止项；只调整平台语法、压缩密度、素材引用与时间结构。
- 不重新调用类型模板，不生成第二版本，不添加备选风格，不新造Effect层、配乐、台词、转场、慢镜或镜头。
- 总工作流已经绑定素材职责时直接采用；不改成旧版 `@material[...]`，也不额外输出参考素材板块。
- 不因旧合规模板静默替换用户锁定身份、品牌、作品参考或剧情。若目标平台存在明确限制，只指出具体冲突或在用户授权下改写。
- 严格继承用户或上游指定总时长；缺省按当前内容选择，不由平台原生上限反推叙事时长。
- 继承上游实际的检查方式：`an-scene-workflow` 的一次关键因果与格式合并检查即可，不补造状态账本、旧质量门或外部脚本；`anime-video-prompt-workflow` 则使用其自身质量门。编译后只核对被改动部分与下游承接；压缩若删除锁定动作、反应、空间承接或声音事件，撤销该压缩，不静默省略。
- 用户或上游已选模板时保留标题层级、角色代号、景别、段首镜头预告和段内时间锚点。平台推荐字段顺序是内容覆盖提示，不覆盖用户格式，也不要求每一镜重复主体、环境和风格。不得为填字段新增配乐、特效或台词。
- 上游已给出正文及事实时直接编译，不重新询问、加载类型模板或跑下面的独立创作流程。只读取当前确需且尚未读取的平台配置。

## 独立创作工作流（无上游场景稿时执行）

### 1. 收集必要信息

先继承用户已给出的模型、时长、风格、比例、素材和模板信息，不重复询问。用户授权决定时长时按剧情与对白容量选择，不机械套默认值。只点名本技能不等于指定Seedance版本；不得凭自选时长推断版本或承诺单次生成能力。只有缺失项会实质改变结果时才一次性确认。

需要确认时使用简短选项：
- **视频时长**：按当前内容与已核验目标平台能力选择；明确2.5已经由上方专项处理。
- **视频风格**：
  - 动作/战斗/追逐
  - 仙侠/奇幻/史诗
  - 产品/电商/广告
  - 短剧/对白/情感
  - 变身/变装/转场
  - 舞蹈/MV/卡点
  - 生活/治愈/Vlog
  - 科幻/机甲/末日

**可选信息（如果用户已提供则跳过）：**
- 视频比例：16:9 / 9:16。用户未指定时，单张主视觉图继承其画幅；多张主视觉图比例一致时继承共同比例；素材比例冲突、纯文字请求，或仅提供角色身份图/道具图/风格图等非主视觉参考时默认 16:9。非主视觉参考不得决定画幅。
- 是否有参考图片/视频素材

> 一次性问完，不要分多轮问。

### 2. 选择模型配置

| 目标 | 时长处理 | 提示词结构 |
|---|---|---|
| Seedance 2.0 / 旧版即梦 | 单段 4–15 秒，超出时延长或拆段 | SCELA + 紧凑动作节拍 |
| Seedance 2.5 / SD2.5 | 转上方2.5专项，不运行本表其他分支 | 由 `seedance-2-5-prompting` 继承原格式适配 |
| 平台未指定 | 采用用户或上游时长；独立任务未指定时按内容建议 | 平台中立中文提示词 |

明确2.5时由专项读取唯一配置源 [seedance-2-5-official-profile.md](references/seedance-2-5-official-profile.md)。仅说30秒或官方模板不能确定版本；不得因此套用本页2.0拆段规则。

### 4. 独立创作模式使用 SCELA 公式展开

总工作流编译模式只把已批准内容映射到对应字段，不用SCELA新增创意。

- **S** Subject — 主体：保留用户提供的人物、作品参考、品牌、身份与核心外形；只有用户明确要求匿名化，或目标平台返回具体拒绝且用户授权最小改写时，才替换相关元素
- **C** Camera — 镜头：从词汇库选最匹配的运镜
- **E** Effect — 特效：具体化，不说「炫酷」，要说「蓝色电弧绕剑旋转」
- **L** Light/Look — 光影风格：色调 + 画质关键词
- **A** Audio — 音效：独立一行，环境音 + 关键音效

**身份与引用原则：**
- 不因模板预判而静默替换用户提供的人名、作品参考、品牌或身份。
- 用户要求原创化或平台已返回具体拒绝时，只改动造成冲突的最小字段，并保留用户确认的剧情、色彩、服装、道具和动作功能。

---

### 5. 选叙述结构（不强制时间戳）

- **流畅叙事**（优先）：`镜头跟随主体动作，场景转换，特效，音效` — 适合追逐/变身/日常/广告
- **时间戳分镜**（仅需精确时序时用）：`0-Xs：画面 / X-Ys：动作 / Y-末：收束` — 适合短剧台词/多段史诗

---

### 6. 合规检查（内部处理，不向用户说明）

> [compliance.md](references/compliance.md) 是Seedance 2.0旧版经验资料，只在独立模式遇到平台明确拒绝且用户要求修复时按需读取。总工作流编译模式不做预防性读取或静默改写。

只检查目标平台已明确显示的限制或实际失败信息。不得仅因出现真实人名、作品参考、品牌或政治题材就自动替换或拒绝；需要改写时指出具体冲突并取得用户授权。

**合规提示词作为内嵌约束处理，不在输出中单独列出"禁止：..."行。**

---

### 7. 输出格式

**5s短版（目标明确）**：直接输出提示词，紧凑简洁。

**10s/15s 完整版**：
```
**主题**：X  **时长**：Xs  **比例**：16:9/9:16

[提示词]
```

默认只输出一个最适合目标的版本。只有用户明确要求多版本、A/B方案或风格对比时才生成多个版本。

**Seedance 2.5**：已在上方专项分支交付，本页不另定义30秒模板、缺省节拍数或延长能力；实际提交仍交 `ai-video-pipeline`。

**Seedance 2.0 超长版（>15s）**：分段，每段 ≤15s，后续段用「将@视频1延长Xs」衔接，标注衔接点。

**输出注意：**
- 不输出「禁止：真实人脸、版权IP...」等说明行
- 不输出「参考素材」板块
- 不输出「风格调整建议」「素材建议」等任何额外说明
- 直接给出可用的提示词，输出完就结束
- Seedance 2.0 的10–15秒提示词，在上游未指定镜头数时可按4–7个可执行镜头或等量事件节拍组织；上游已定镜头/分镜时保留，不压缩。每个时间块只承担一个主要局势变化，外观与场景锁只完整写一次，负面约束只写实际高风险，允许为零且通常不超过8项；此数量建议不覆盖用户格式或上游已定稿。
- 仅交付提示词时，在当前回复内人工核对时间段连续覆盖总时长、`t=`位于所属段内且递增；不为检查而自动创建文件或运行脚本。联用时服从上游已选的轻量检查方式，不重复校验。
- 用户要求保存/检查文件、专项测试或修改检查器时，才按需运行 [validate_timeline.py](scripts/validate_timeline.py)：`python scripts/validate_timeline.py <UTF-8文件> --duration <目标秒数>`。该脚本只校验宏观时间范围与总时长，不验证段内动作、`t=`事件或成片质量；目标时长缺失必须失败。允许`0–6秒`及`【0–6秒｜标题】`等合法装饰，不应为迁就解析器改坏已选模板。

## @引用规则

- 用户上传图片时：使用 `@图片1`、`@图片2` 等，并在首次出现时写清每张素材的主要职责；兼容的服装、发型、随身武器等次要继承项可同时声明，禁止继承项不得带入
  - ✅ `@图片1为首帧，@图片2为尾帧`
  - ❌ `虚拟科技大亨（参考@图片1）`
- 命名：使用目标界面实际显示的 `@图片N` / `@视频N` / `@音频N`；不要用旧数量上限截断用户已提供的有效素材
- 用途在提示词中明确：`@图片1为首帧` / `参考@视频1的运镜` / `背景音参考@音频1`
- 为每个素材指定一个主要职责，并继承总工作流批准的兼容次要属性和禁止继承项；不把冲突素材并列为同等控制源，也不从角色肖像自动继承背景、站姿、景别或光向。
- 引用标记使用当前界面真实插入的形式，可能带空格，也可能不带；沿用既有编号、大小写与语言，不为迁就样例重写真实标签。

## 延长连续性协议

超过单次上限或用户明确要求延长时，在内部为每个段尾建立终态快照：角色位置与朝向、彼此距离、姿态和动作惯性、左右手持物、伤势与服装变化、环境破坏、主光与色温、特效残留、声音相位、摄影机终点和运动方向。内部标签不得进入最终提示词。

每个延长段遵守：

1. 以当前界面真实引用标记开头，例如 `将@视频1延长Xs`，不得把延长时长写成平台未核验的固定值。
2. 用一句紧凑自然语言承接上一段最后一帧，只写必须保持的终态与仍在持续的动作，不重复整段全局设定。
3. 延长段首拍从上一段的动作惯性、视线、摄影机方向和声画相位继续；不得重新建立站位、恢复伤势、交换持物手、重置环境或突然切换轴线。
4. 如果上一段结束在接触、腾空、挥击、爆炸形成或运镜途中，延长段先完成该未决动作，再进入新事件；不能在段界把动作跳完。
5. 每段结尾都留下可验证的结果或下一段入口。若当前界面不支持所需延长轮数，明确报告容量冲突并拆为独立片段方案，不虚构能力。

## 动态锁与增量编译

继承上游动作相位、防线/控制状态、余势、人物下一任务和允许的摄影变化，不把一致性压缩成全程固定姿态/构图。身份/道具/素材职责与运动中的表情、支撑、视差分开；明确静态/母版要求仍遵守。补强正向过程后才补具体负面项，不以“不要摆pose”代替动作句。来源模板和默认十五秒/镜数/单峰/拆片建议不替换上游已定时长、密度与声画分栏，2.5仍只转交一次。

## 精彩度的增量编译的参考学习增量

继承上游已选期待/变化/主峰、人物选择、动作乐句、技能辨识和快慢/加载关系，写入原声画栏；引用只绑定真实素材职责，不以参考片时长或神器改上游，也不压缩掉作用与后果。按需读[有关方法](../an-workflow/references/battle-excitement-direction.md)，联用只补本职责，不重导演。

## 完整版剧情攻防的执行增量

沿上游原稿一次编译，保留器具/控制肢体、目标反应、接重、材料相位和跨镜残留；不把源片120fps、选择帧时间、技能数或时长变成平台参数。只在当前已选版本和模式处理语法，未知来源与声音不补造。具体关系按需读[剧情攻防执行方法](../an-workflow/references/narrative-combat-transfer.md)；仅回填本职责，不重新导演整场或强制读源报告。

## 最新学习的职责内执行

一次编译继承上游已选的角色战法、信息顺序、当前法术相位与画外并行；压缩不合并掉重要脸/手/对手镜的观看职责，不把切回译成再次起手。按需读[信息覆盖](../action-camera-direction/references/information-led-coverage.md)定位丢失项，保留原格式/时长/密度，只适配真实平台标签与语法，不自动上传或生成。
