# Hell Grind：AI 电影资产与视频管理经验总结

> 最值得学的一件事：先确定角色、地点和道具，再按场景生产镜头；用统一名称把图片、文字、提示词和视频连起来。

来源：[Hell Grind 公开项目页](https://higgsfield.ai/@higgsfield.studio/projects/hell-grind)。整理日期：2026-10-01。

本文依据公开页面的文件夹列表与制作说明整理。具体生成经验来自团队自述，并非保证所有模型都有效的规则。下面的本地目录和文件命名模板是整理建议，不是他们实际目录的完整复刻。

## 一、先看懂整个流程

```text
剧本与场景划分
      ↓
准备资产：角色图、地点图、道具图 + 固定文字描述
      ↓
测试资产：换姿势、换光线、多人同框
      ↓
确定资产名称、状态、场景空间地图
      ↓
按场景写镜头表和视频提示词
      ↓
生成视频 → 检查 → 记录修改 → 再生成
      ↓
边生成边剪辑，发现缺什么就补什么
      ↓
画面修复 → 调色 → 声音与音乐 → 输出
```

**文件管理的目的：随时知道一个视频用了哪些资产、哪个提示词版本，以及为什么选它。**

## 二、项目的文件夹怎么分

公开页面可以看到以下类型：

| 类型 | 页面中的名称示例 | 可以怎样理解 |
|---|---|---|
| 总入口 | All assets | 全部资源的浏览入口 |
| 基础资产 | Assets | 集中管理基础资源的入口；具体子分类需进一步查看 |
| 剧情段落 | 1. COLD OPEN、Flashbacks、Scene Orphanage | 按开场、闪回等段落组织 |
| 场景编号 | Scene 13、Scene 14、Scene 15-16 | 按剧本场景组织生产 |
| 编号加内容 | Scene 25 Roko vs Robots、Scene 36 Jaxx's Fall | 名称直接提示该场戏的内容 |
| 细分场景 | Scene 27.1、Scene 27.2、Scene 73.1B | 给复杂段落拆分工作单元 |
| 重生成 | Regenerations | 单独设有重生成分类；具体收录范围未逐项核验 |
| 其他分类 | Credits、Series | 页面中另设的项目分类 |

**规律：按“这段剧情需要什么”组织，比只按 JPG、MP4 文件格式分堆更方便生产。**

注意：页面存在同名场景和混合编号，不适合原样照搬。文件夹旁的数量不能直接当成最终镜头数，也不能据此计算有效视频数量。

## 三、资产是什么：图片和文字要成对保存

| 资产 | 图片负责什么 | 固定文字负责什么 |
|---|---|---|
| 角色 | 脸、体型、服装、外观 | 稳定的身份特征和当前外观状态 |
| 地点 | 建筑、材质、空间外观 | 空间特点、光线逻辑和辨识物 |
| 道具 | 形状、颜色、材质 | 尺寸、使用方式和当前状态 |

固定文字描述在原文中叫 **descriptor**。可以把它理解成“这个资产的标准说明”。

例如：`roco_reference.png` 和 `roco_descriptor.md` 属于同一个资产。只留图不留描述，后续很难稳定复用。

## 四、角色图的经验

### 1. 角色表有三种核心视图

- 清晰的脸部近景，团队推荐较大的 3/4 视角头像。
- 正面全身，用来说明服装和体型。
- 背面全身，用来说明背部外观。

**他们的特殊做法：正面全身人物不保留头部。**

原因是避免视频模型从全身小图里读取模糊的脸，让它从清晰头像读取五官。这是他们的经验，可以小规模测试后再采用，不必默认所有模型都需要。

### 2. 角色表要清楚、朴素

| 建议 | 用途 |
|---|---|
| 中性灰背景、平光 | 便于辨识外观，也便于适应不同场景光线 |
| 保留毛孔和真实皮肤细节 | 减少塑料感 |
| 检查眼睛里的光点 | 帮助角色看起来有生命感 |
| 避免强烈滤镜、颗粒和预先固定的电影光效 | 减少角色图把自身风格带进所有镜头 |

角色图首先服务于“这个人是谁”；具体镜头的电影感交给场景和视频提示词。

### 3. 局部修改，保护原始图

团队修改衣服、伤口和血迹时，先生成局部变化，再用图像编辑软件的蒙版合回原图。

```text
原始角色图 → 生成需要改变的部分 → 蒙版合成 → 新状态资产
```

你的合成经验可以直接用在这里：只替换变化区域，尽量保留脸部、皮肤和其他不变部分。避免反复把整张图送进模型导致细节和颜色漂移。

## 五、不同状态，分别建立资产

| 对象 | 状态示例 | 标签示例 |
|---|---|---|
| 角色 | 普通、湿身、带血、换装 | `@roco`、`@roco_wet`、`@roco_blood` |
| 地点 | 白天、夜晚、雨天 | `@loc_base_day`、`@loc_base_night`、`@loc_base_rain` |
| 道具 | 完整、带血、握在手里被遮住 | `@artifact_full`、`@artifact_bloodied`、`@artifact_hidden` |

每种状态都配自己的图和描述。不要在一个资产说明里同时混入几种相互冲突的状态。

**只建立剧情实际需要的状态。** 资产锁定后也可以修改，但要增加版本，并标明哪些镜头会受影响。

## 六、地点图要能支持拍摄

### 1. 优先表达空间深度

团队推荐 3/4 视角地点图，让模型看到纵深。正面“漂亮照片”可能缺少侧面信息，换机位时更容易凭空补建筑。

### 2. 每个地点设置辨识物

例如门、柱子、灯、沙发、祭坛。人物站位围绕这些物体描述：

| 模糊写法 | 更明确的写法 |
|---|---|
| 他站在房间里 | 他站在门内侧两米处，面向中央训练垫 |
| 她在他左边 | 她位于画面左侧，靠近柱子 |
| 光线很电影感 | 主光从右侧窗户进入，人物朝摄影机的一侧较暗 |

### 3. 反打角度的两种办法

1. 以原地点图为依据，生成同一空间的另一侧，检查建筑和光线能否接上。
2. 生成空场景缓慢移动的探索视频，截取需要的角度，再修复画质。

第二种是团队后期发现的办法。截帧仍需核对空间关系，模型生成的探索视频不等于真实三维场景。

## 七、统一名称：让所有文件能互相对应

团队在文档、提示词和平台界面中使用同一套 `@标签`，如 `@roco`、`@loc_cave_front`。

建议用一张资产登记表管理：

| 标签 | 类型与状态 | 参考图 | 描述文件 | 版本 |
|---|---|---|---|---|
| `@roco` | 角色，普通 | roco_reference_v01.png | roco_descriptor_v01.md | v01 |
| `@roco_blood` | 角色，带血 | roco_blood_reference_v01.png | roco_blood_descriptor_v01.md | v01 |
| `@loc_base_day` | 地点，白天 | base_day_reference_v01.png | base_day_descriptor_v01.md | v01 |

**标签是身份，版本是修改历史。** 名字确定后尽量稳定，避免同一人出现多种拼写。

在其他平台使用时，需要把标签对应到实际上传或选中的参考图。仅在提示词中打出 `@roco`，不代表模型自动拥有那张图。

## 八、生成前先测试资产

团队说明中的标准是：测试约十次不同姿势和光线，并检查多人同框时是否仍然稳定。

- 换近景和远景，脸是否一致？
- 换光线和姿势，服装、体型是否一致？
- 与其他角色同框，是否串脸、复制人物？
- 进入正式场景，道具和角色比例是否正确？

测试通过，再作为正式资产使用。失败时检查图、描述、引用方式和模型表现；不要只靠增加重试次数。

## 九、每场戏固定一份空间地图

原文叫 **GEO SPATIAL LAYOUT**。它是一段可重复使用的空间说明。

```text
场景：训练室
中央：圆形训练垫。
门：位于远端墙面，当前主机位画面左侧。
长凳：位于训练垫右侧，两米外。
主光：来自训练垫上方。
摄影机：始终停留在门这一侧，不越过本场戏的轴线。
```

空间地图负责房间结构，地点资产负责外观；每个镜头另外写人物站位和视线。

**下一条视频不会自动记住上一条的站位。** 每次生成都重新说明。更换机位后，要重新核对画面左右，不能机械复制左右位置。

## 十、视频提示词固定结构

| 部分 | 用简单的话理解 |
|---|---|
| 场景背景 | 发生什么、谁出现、时长多少 |
| 参考资产 | 用哪些图，每张图负责什么 |
| 空间地图 | 门、物体、光源、摄影机在哪里 |
| 首帧与站位 | 第一帧谁站哪里、看哪里 |
| 拍摄方式 | 一镜到底还是包含切镜 |
| 镜头与焦点 | 景别、镜头感觉、谁清晰 |
| 摄影机 | 如何移动、保持什么位置 |
| 动作时间表 | 每一段时间发生什么 |
| 物理与光线 | 重量、接触、惯性、照明 |
| 声音 | 固定声线、准确台词、环境声 |
| 表演 | 想得到什么、隐瞒什么、身体如何反应 |
| 风格与约束 | 共用风格、人物与道具数量、画幅等 |

引用图片时说明用途，例如“角色外观参考”“地点空间参考”。团队对地点图特别说明：只取空间和材质，不把原图当首帧，也不照搬构图和角度。

**资产参考图不一定是视频首帧图。** 前者说明对象长什么样，后者规定镜头从什么画面开始。

## 十一、让镜头更容易生成的技巧

| 问题 | 团队采用的办法 |
|---|---|
| 人物换位置、空间混乱 | 用约一秒宽镜头先确认位置，再进入动作；按具体镜头测试 |
| 人物僵硬 | 写呼吸、视线、停顿、手部动作等可见变化 |
| 情绪空泛 | 写角色目标和身体反应，例如听见一句话后手上的工作停下 |
| 人数、道具数量变化 | 明确“恰好三个人”“一张桌子”，并提供对应参考 |
| 动作太复杂 | 一镜集中完成一个主要动作，必要时拆镜 |
| 破门等动作不发生 | 从动作已经开始的瞬间切入，把接近目标另拍一镜 |
| 跨场景衔接不自然 | 用门口等过渡位置，说明两个地点和两边光线 |
| 巨大角色变小 | 给出明确尺度，并放入人物等可见尺寸参照 |
| 群众数量不稳定 | 群众作为整体资产，重要近景人物另建资产，说明数量 |

时间段里的动作保持简单。提示词长不等于更稳定，关键是每个时间段是否清楚、能执行。

团队的一秒宽镜头、长提示词等做法是经验方案，不是所有镜头的强制要求。提示词中的“8K”也不等于实际输出分辨率，仍要看平台设置。

## 十二、声音和表演也要有固定档案

角色除了图，还应保存：

- **声音说明**：音域、语速、口音、说话习惯；每次对白复用。
- **行为说明**：走路节奏、眼神、手部习惯、紧张时如何反应；随场景调整具体动作。

团队把台词集中在声音部分，逐句写清由谁说，避免模型自行补话。生成时不加音乐，保留对白和现场声音，音乐在后期制作。

镜头衔接也要保留上一镜的情绪余波：呼吸、手的颤动、视线和动作不要突然恢复正常。团队还尝试在新生成片段开头带入上一句的尾部，帮助对白接上；剪辑时要处理重复内容。

## 十三、按场景生成，保留每次修改

每个剧情段落有自己的镜头表，每镜记录编号、时长和完整提示词。固定资产描述和共用风格从同一份标准内容取用。

```text
确定一个场景 → 生成该场镜头 → 放入剪辑 → 找出缺口 → 补镜或重做
```

重生成记录可以很简单：

| 镜头 | 版本 | 只修改了什么 | 结果 | 状态 |
|---|---|---|---|---|
| S02_SH003 | v01 | 初次生成 | 手部穿模 | 未通过 |
| S02_SH003 | v02 | 简化抓门动作 | 手部正确，脸漂移 | 未通过 |
| S02_SH003 | v03 | 调整脸部参考 | 表现可用 | 待剪辑确认 |

**一次尽量只改一项，保留原提示词和视频。** 才知道哪个改变有效。

团队采用约十到十五次失败就重新考虑镜头的办法：拆镜、删动作、换角度。这是停止无效重试的参考阈值，可按预算更早停止。

共用描述更新后，应记录新版本；已经生成的镜头不会自动更新，旧提示词也要保留才能追溯。

## 十四、剪辑和后期的经验

- 边生成边剪辑，让剪辑反馈缺少的手部特写、反应镜头、宽镜头。
- 检查片段头尾，团队常裁去约半秒；实际按动作和对白决定。
- 画面定剪后、调色前做清理，优先检查脸、手、文字和跳动的纹理。
- 小问题逐帧修复，严重错误用保存的提示词重生成。
- 调色先统一相邻镜头，再完成整体风格。
- 对白做降噪和音色统一，用连续环境声连接不同生成镜头。

## 十六、最小执行清单

### 开始生成前

- [ ] 角色、地点、道具都有参考图和固定描述。
- [ ] 需要的换装、受伤、昼夜状态已分开。
- [ ] 标签与文件名能够对应。
- [ ] 资产做过换光线、换角度和同框测试。
- [ ] 当前场景有空间地图和镜头表。

### 每次生成后

- [ ] 检查身份、状态、站位、手部、道具和声音。
- [ ] 保存视频和完整提示词，使用同一版本号。
- [ ] 记录修改内容及通过或失败原因。
- [ ] 放进剪辑检查衔接，再决定是否选用。

**第一次只做一场戏：一个角色、一个地点、几个镜头。先把命名、引用和版本记录跑通，再扩大规模。**
