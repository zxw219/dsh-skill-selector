## 1. 项目圣经

在分集写作前锁定以下事实：

- Logline、主情绪、情绪内核、结局方向；
- 主角 Want / Need / Lie / 关键选择；
- 世界规则、能力边界、代价和禁止事项；
- 主要关系的起点、阶段变化与终点；
- 全剧序列、付费节点和关键回收位置；
- 不能改动的生产限制或 IP 设定。

任何后续修改若改变其中一项，评估对已完成集数和后续节点的连锁影响。

## 2. 角色状态表

每完成一集更新：

| 角色 | 物理状态 | 情感状态 | 关系状态 | 当前目标 | 已知信息 | 隐瞒信息 | 下集必须延续 |
|---|---|---|---|---|---|---|---|
| 角色名 | 位置、伤势、持有物 | 具体变化 | 与关键角色的变化 | 可执行目标 | 该角色确知 | 该角色隐瞒 | 未完成动作/后果 |

区分“观众知道”与“角色知道”。不要让角色使用尚未获得的信息。

## 3. 故事线与弧光预算

同时运行的主要故事线保持可识别：

| 故事线 | 当前问题 | 最近推进集 | 当前阶段 | 下次推进 | 与主线的关系 |
|---|---|---|---|---|---|
| A 主线 |  |  |  |  |  |
| 关系线 |  |  |  |  |  |
| Running Subplot |  |  |  |  |  |
| 暗线 |  |  |  |  |  |

为长弧光预留变化空间：

- 前段建立 Lie 和旧策略，不急于完成真正成长；
- 中段允许伪变化、反复或错误领悟；
- 后段让关键选择消耗最大的弧光额度；
- 结局用行为展示新常态。

不是每集都必须发生内在成长，但每集必须改变局势、关系、认知或行动条件。

维护情绪内核推进表，防止中段跑题或同类桥段重复：

| 集/序列 | 剧情事件 | 情绪功能 | 使用的冲突机制 | 与上次的差异 | 内在状态变化 |
|---|---|---|---|---|---|

## 4. 伏笔和信息差

### 埋种 / 回收表

| 种子 | 表面功能 | 深层含义 | 埋入集/场 | 提醒位置 | 回收集/场 | 状态 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  | 待埋 / 已埋 / 已回收 |

让伏笔第一次出现时具有当场的表面理由；回收时改变观众对旧信息的理解。长期伏笔需要适度提醒，但不要反复特写到暴露功能。

### 信息公开表

| 信息 | 观众何时知道 | 哪些角色知道 | 哪些角色误解 | 释放方式 | 造成的行动变化 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

让揭示改变行动，而不是只增加百科知识。

## 5. 记忆检查点

每完成一个序列、3–5 集或一批写作任务后，生成：

```text
【当前位置】完成到第__集 / 序列__：
【故事核心】Logline / 当前总目标与阻碍：
【最近变化】每集一句：事件 + 价值变化：
【角色状态】仅记录本批次发生变化的角色：
【活跃故事线】当前问题 / 最近推进 / 下一节点：
【伏笔状态】已埋未收 / 本批回收 / 新增种子：
【信息差】观众知道 / 各关键角色知道与误解：
【节奏状态】上一集外部 / 内部强度；下一集建议：
【下一步】下一集观看问题、主角目标和开场动作：
```

只记变化和后续必需信息，不复述全文。跨对话继续创作时，先读取最近检查点与项目圣经。

## 6. 批次冻结与滑动窗口

- **批次冻结**：每 10 集（或一个序列）为一批。一批写完，经审稿（`red-team-review.md`）和修改后冻结，冻结内容不得静默改写；需要改动时向用户说明影响范围；
- **停机审查**：冻结后停下，向用户展示审稿意见与最终结果，等用户确认再进入下一批（七步流程中与步骤 5 的确认门合并，不重复停顿）；
- **滑动窗口衔接**：审查第 N 集时同时看第 N 集结尾和第 N+1 集开场，确认上一集的钩子被具体承接，而不是各集孤立通过；
- 冻结时更新第 5 节的检查点。

## 7. 核心锚点（精简版）

除完整检查点外，另生成一份不超过 500 字的核心锚点，供跨对话快速恢复，内容只含：

```text
主角人设与禁忌 / 核心矛盾 / 主线进度 / 各感情线当前亲密等级 /
已公开与未公开的关键信息 / 必须延续的 3–5 件事 / 下一集开场动作
```

新对话开始写作前，先读取核心锚点，再按需读取完整检查点。核心锚点也是防止人物降智和设定遗忘的手段：反派不做不符合常理的蠢事，主角不为推动剧情而降智。

发现人物行为与已定性格、处境或目标对不上时，不要直接改性格去迁就剧情，按 `core-methodology.md` 第 3 节“人物闭环自检”的顺序排查；排查后仍有逻辑断层，先停下向用户请求补充。

## 8. 用户偏好回写与人设风格抽屉

**用户偏好回写**：用户修改或指出“哪里不对”后，对比原稿与修改稿，找出“作者以为对、用户觉得不对”的落差（删掉了哪种连接词、把长句拆成几个短句等），记入检查点的“用户偏好与禁用词”一栏，并简短汇报“已记录：……”，之后的生成按此执行。

**人设风格抽屉**：角色的神态、口吻、表演方式要绑定题材和人设标签，各自独立记录，专剧专办：

- 底层通用规则（格式、体量核对、反机械切片、原创核对）对所有项目生效；
- 人设风格（冷面、反差逗比、克制含蓄等）只在对应人物身上激活，不套用到其他人物，也不带到下一个项目。

跨对话时，用户偏好与人设风格抽屉随检查点一起保存和读取。
