## 1. 使用边界

用户说“对标《X》写《Y》”“参考 X 写第 N 集”“按 X 的结构写”“1:1 继承节拍链”时读取。也适用于用户上传参考小说或分集拆解，要求“同类题材原创”。

本文件规定怎么借节奏，不规定怎么借内容。

## 2. 为什么不能 1:1 继承

一种常见做法是：取对标剧第 N 集的节拍链，只把人名、背景、道具换掉，再写新剧第 N 集。这样做出来的是换皮，不是对标：

- 场次顺序、冲突走向、集尾卡点与原作一一对应，只有表面词不同；
- 很容易连带复现具体台词、数字、比喻，造成近乎逐句的台词重合；
- 版权、同质化和平台审核风险都会上升；
- 审稿时按 `text-quality-originality-check.md` 第 8 节会判为“局部相似”或“高度同构”。

## 3. 可以提取什么，不可以继承什么

**可以提取（功能层）**：

- 节拍的功能序列，例如“施压 → 升级 → 反制 → 定格”，用功能语言记录，不记录具体动作；
- 情绪波形的形状与强弱；
- 集尾卡点的**类型**（信物掉落、第三方闯入、身份亮相等）和断点所处的情绪极值；
- 集间承接的方式（空间延续、情绪延续、台词呼应）；
- 信息差的类型（谁知道、谁不知道、观众处于哪一侧）；
- 兑现层级（见 `payoff-mechanics.md`）。

**不可以继承（表达层）**：

- 具体台词、数字、专有比喻、口头禅；
- 具体道具、场景、场次顺序的一一对应；
- 人物关系配置的一一对应（谁背叛谁、谁是谁的靠山，整套搬）；
- 独特桥段和标志性名场面。

## 4. 三步流程

1. **拉片**：用第 5 节模板记录功能层，不摘抄原句。记录本身也不写具体台词和数字；
2. **换轨**：新写的集至少在以下四项中更换两项：冲突场域、核心道具或机制、人物关系配置、节拍顺序。只换名字不算；
3. **写后核对**：把关键台词和场次结构与源文本逐句、逐点比对（`text-quality-originality-check.md` 第 8 节）。发现具体数字、比喻、专有搭配或场次顺序重合，一律重写。这一步必须在交付前做，不等用户要求自检。

## 5. 拉片模板（功能层）

每集记录，用功能语言，不抄原文：

```text
① 定位与功能：本集在全剧中承担什么（起势、加压、转折、兑现、收束）
② 开场承接：怎样接上一集（动作、空间、情绪、台词呼应）
③ 节拍链：5–7 个功能节拍（如 挑衅 / 危机 / 反制 / 定格），每个只写功能与情绪值
④ 冲突与对抗力量：利益争夺点、敌意的性质
⑤ 结果反馈：即时释放还是延迟释放
⑥ 兑现或情感机制：爽点或情感点从哪里来
⑦ 信息差：谁知道、谁不知道，观众在哪一侧
⑧ 情绪波形：起点 → 极值 → 终点
⑨ 反派或配角动机：为什么这样做
⑩ 集尾卡点：卡点类型，断在哪个情绪极值，反应是否留给下一集
```

## 6. 用户明确要求“1:1 继承”时

- 说明风险：换皮式继承易与原作雷同，并带来版权与审核风险；
- 默认改为功能层继承，并说明这样做能保留节奏、避开表达层复用；
- 若用户坚持更贴近原作，可以在功能层贴得更近（节拍顺序、卡点类型、集间承接、情绪波形）；表达层照旧不越线：台词、数字、比喻、标志性桥段、整套人物关系配置不复现。用户要求越过这条线的部分，不执行并说明原因，其余照做；仍执行第 4 节第 3 步，并如实报告相似位置；
- 无论如何，不复述、不复现源文本的具体台词。

## 7. 节省篇幅的做法

- 不向上下文塞入整集原文，只取对应集的功能层拆解条目；
- 写第 N 集时，只对齐对标剧第 N 集的功能层条目，不同时读取整部原作；
- 拆解文件较大时，只读取所需集数对应的段落。
