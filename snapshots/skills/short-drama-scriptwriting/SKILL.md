# 付费短剧 / 漫剧编剧与终审（国内 / 海外）

把作品写成一条持续改局的观看承诺：**每集解决一个局部问题，用不同剧情再次触碰同一个情绪内核；每场让人物在具体处境里争夺目标，每轮对白或动作改变信息、关系、筹码、理解或选择，同时保留真实的人声、潜台词、反应和余震。**

## 铁律（优先级最高，覆盖所有步骤）

### 七步强制确认

完整创作任务固定按第 1 步至第 7 步顺序执行，七步全部是用户可见交付，不得合并、跳过或降为内部步骤。每次只提交当前步骤的完整结果；内部分析和读取参考不单独设确认点。

局部任务（重写/续写某几集或某场、检查冲突、提问诊断、单次自检、术语或格式修改等不要求从概念到正文完整推进的任务）不进入七步确认门，直接完成并交付，不追加确认口令；仅在同一轮对话内被要求转为完整创作（从概念或立项开始逐步推进）时，才从对应步骤起进入七步流程。

开始步骤 1 前，先向用户说明：

> 这个技能不会一次写完整部剧本，而是逐步推进。每一步结束后，你可以回复“通过”“修改”或“自检”。

每个步骤末尾必须原样附上以下三行，然后停止：

回复 **[通过]**：进入下一步；若为步骤 7，则确认完成
回复 **[修改]**：直接说明修改要求，例如“把主角改成女性记者”
回复 **[自检]**：检查当前步骤的逻辑、节奏、台词和可拍摄性

- 收到 `[通过]`：锁定当前步骤，再进入下一步；后续不得静默改写。连续性迫使调整时，先说明影响并重新确认。
- 收到 `[修改]`：留在当前步骤，只重发受影响内容，随后再次提供三行确认口令。
- 收到 `[自检]`：留在当前步骤，显式检查并修正，提交修订版后再次提供三行确认口令；`[自检]` 不等于 `[通过]`。
- 同时识别带方括号和不带方括号的“通过”“修改”“自检”。意图不明确时，不得擅自进入下一步。
- 即使用户要求“一次完成”“连续输出”或“直接全部写完”，也不得越过确认门；除非用户明确要求修改或取消本条规则。

### 输出前自检

每一步输出前先内部检查逻辑、因果、节奏、情绪、台词、格式和可拍摄性。发现问题先修正再提交，不展示冗长的内部过程；只有用户回复 `[自检]` 或明确要求报告时，才展示检查结论。

### 短剧写作红线

- 只写可见、可听、可表演的内容，不用心理说明、主题说教或解释性对白替代表演。
- 每轮对白必须产生增量：增加有效信息、推进目标、改变筹码、刺中伤口、迫使选择、改写理解或触发行动；允许少量有表演价值的反应拍，但不得连续空转。
- 不让人物句句完整、正确、锋利或像作者总结。自然度、人声和人物当下能说到哪一步优先于功能百分比；用户反馈“太 AI”时强制读取 `references/human-dialogue-emotional-rhythm.md`。去 AI 腔不等于删掉感情：关键心意可以藏、漏，或在里程碑场明牌，见 `references/romance-tension.md`。
- 文本质量与原创自检：交付前按 `references/text-quality-originality-check.md` 检查文笔口水、重复对话标签、逻辑与法律、冗余与环境描写，以及导语与衔接是否套用原作模板（需用户提供原文才能比对，无原文时如实说明只能做通用模板化检查）。用户给出情感标签（虐、甜、酸涩、强制爱、伪骨科、双强、破镜重圆、病娇、疯批、阴郁、救赎、双向救赎）时，读取 `references/genre-emotion-tags.md`。
- 题材与驱动锁：立项时只选一个主驱动（情感关系 / 事业利益 / 家庭亲情 / 悬疑侦破），其余只做辅助；未选择悬疑侦破时，不得把主要冲突写成“找线索、取证、对质、还原真相”，信息差优先用于情感效果，不用于解谜。用户反馈“又变成破案”时，强制读取 `references/genre-drift-guard.md`。
- 感情戏必须有可拍的关系表现：好意不得全部功利化（有奖励或兑换才对她好），强势方至少露出一次软肋（无回报付出、付出代价或失手泄露），内心独白不得复述台词与动作已表达的心意。用户反馈感情戏弱、没感觉或拉扯不足时，强制读取 `references/romance-tension.md`。
- 剧本按 `references/script-format.md` 输出：“场X-Y 【内/外·日/夜】地点 / 人物： / △ 动作 / 角色名（情绪）：台词 / —— 镜头提示”，场景、动作、台词、情绪四要素齐备；场次行不追加逐场秒数。
- 每集必须有阶段性回答和向前拉力；钩子由末场最后 1–2 行完成，并在集末加一行 `【集末钩子】` 标签（用户不需要时可省略）。
- 当用户提供参考/源文本用于同类题材原创任务时，不能只凭"已换名字设定"的印象判断是否原创：写出关键台词、场次结构后，必须与源文本逐句/逐点核对（读取 `references/text-quality-originality-check.md` 第8节），发现具体数字、比喻、专有搭配或场次顺序与源文本重合，一律视为需要重写，不得以"同类题材常见写法"为由保留；步骤1的立项台词、步骤5每一批正文交付前都要做这一遍核对，不能只在用户要求"自检"时才做。
- 用户要求“对标/参考某剧写”时，只继承功能层（节拍功能、情绪波形、卡点类型），不做换名字式的 1:1 继承，见 `references/benchmark-alignment-safe.md`；用户明确坚持时说明风险；功能层可以贴得更近，表达层（台词、数字、比喻、标志性桥段）不复现，仍执行写后核对并如实报告相似位置。
- 不复刻具体作品的受保护台词与独特情节；IP 项目先确认授权范围。

## 项目配置

先提取或合理假设以下配置：

- 交付阶段：创意 / 立项 / 大纲 / 集纲 / 正文 / 审核；
- 载体与市场：真人短剧 / 漫剧 / 动态漫画；目标市场（国内 / 海外，无默认值；完整创作、立项、本地化和涉及法律合规时，未说明必须先问用户）；目标平台；
- 受众、主情绪与情绪内核：男频 / 女频 / 泛受众，爽 / 甜 / 虐后爽 / 悬疑 / 治愈；角色与观众反复被触碰的情感缺口是什么；
- 总集数、单集时长、免费窗口或付费节点；
- 主类型、辅助元素、制作限制、内容边界；
- 对白与反转基准：自然 / 强 / 拉满；允许的羞辱、暴力、情欲和语言尺度；
- 人声与自然度基准：生活口语 / 略高于生活 / 强类型化；主要人物的称呼、句长、礼貌、回避与攻击差异；
- 输出形态：剧本（场景 + 动作 + 台词 + 情绪）/ 小说短篇 / 梗概与导语（默认剧本）；单集目标时长与字数（如需要；默认单集 500–700 字、不超过 3 场）；
- 情感标签：1 个主标签 + 最多 2 个辅标签；结局承诺（HE / BE / 开放 / 甜虐交替）与虐度；情绪档位（主 / 次 / 禁用）；法律与合规参照地域（跟随目标市场：国内项目默认中国大陆现行规定，海外项目需用户说明目标国家/地区，无默认值）；
- 主驱动类型：情感关系 / 事业利益 / 家庭亲情 / 悬疑侦破（只选一种作主线，其余作辅助；见 `references/genre-drift-guard.md`）；
- 感情线配置：主 CP / 多线 / 后宫 / 无感情线；每条线的功能（对手、救赎、陪伴、共犯等）、目标亲密度、内容尺度；平台对多线感情与亲密表达的规则（待核实，以用户给出的最新规则为准）；
- 已有材料与必须保留的设定。

只在缺失信息会实质改变结果时提问。可安全推断时，列出 1–3 条假设后继续，唯独目标市场（国内 / 海外）没有默认值：完整创作、立项、本地化和涉及法律合规的任务，未说明时必须先问用户，不得替用户假设；局部任务（改某几集、某一场、查冲突、单次自检等）不为此中断，按材料本身的语境处理并写明所用假设，涉及法律或平台规则的部分标“待核实”。平台政策、免费集数和付费点可能变化；优先使用用户给出的最新规则，不把参考比例冒充平台现行政策。

## 短剧七步工作流总览

| 步骤 | 核心任务 | 用户可见交付 |
|---|---|---|
| 1. 锻造概念 | 建立高概念、观看承诺和情绪内核 | 概念定位、Logline、目标、阻碍、代价、卖点、名场面 |
| 2. 故事与人物发动机 | 建立人物行动逻辑和长线动力 | 主角/反派/配角发动机、核心戏剧动作、人物弧光 |
| 3. 全剧留存架构 | 搭建因果骨架、序列和付费卡点链 | 全剧大纲、序列、情绪变奏、卡点与回收 |
| 4. 分集规划 | 把全剧拆成可执行的单集 | 分集大纲、集内问题、阶段回答、集末拉力、下集启动 |
| 5. 场景与正文 | 把单集卡转为可拍剧本 | 分场正文（场景、动作、台词、情绪）、每集以钩子收尾 |
| 6. 情绪、对白与关系校准 | 检查双轨节奏、对白交锋、关系变化和虐爽因果 | 校准报告及明确修订内容 |
| 7. 连续性与记忆检查点 | 锁定跨集状态、伏笔、信息和后续约束 | 可保存的连续性检查点 |

完整创作必须依序完成七步。步骤 4 通过后才能进入正文；步骤 5 按用户确认的集数或批次交付，不一次写完整部剧本。每一步都必须执行对应的强制确认门。

## 七步执行细则

### 1. 锻造概念

先建立一个能自带冲突的观看承诺，不强制套用单一“弱者 + 隐藏底牌”公式。

至少明确：

- 主角的可见处境与反差；
- 全剧反复展开的情绪内核，如“渴望被选择却总被替代”“尊严被剥夺后重新夺回”；
- 主角当前必须完成的具体目标；
- 直接阻碍、失败代价和时间压力；
- 秘密、权力差、规则差或关系矛盾；
- 能被画面证明的核心卖点；
- 一句话 Logline 与 1–2 个名场面候选。

用 `references/concept-design.md` 生成和筛选方案。不要只换人物职业却复用同一故事。

本步骤最低交付：概念定位、Logline、核心情绪、主角目标与阻碍、失败代价、核心卖点及名场面候选。

**步骤 1 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；未收到 `[通过]`，不得开始步骤 2。

### 2. 建立故事与人物发动机

读取 `references/core-methodology.md`，用以下链条检查长线动力：

```text
前史压力 / Ghost → 错误信念 / Lie → 行为缺陷 / Flaw
→ 外在目标 / Want ↔ 内在需求 / Need
→ 递进失败 → 关键选择 → 新常态
```

再明确全剧核心戏剧动作：

```text
主角目标 → 核心阻碍 → 每次行动造成的新结果与更高代价
```

不要用人物履历代替行为逻辑。反派与配角至少要有自己的目标、筹码和底线。

锁定一条情绪内核，把它写成“角色的情感缺口 + 反复遭遇的否定 + 最终需要的证明”。区分：主题是作品对问题的判断，情绪内核是观众反复体验的情感张力，剧情则是测试这份张力的不同事件。

若感情线是卖点，读取 `references/romance-tension.md`，为每条主要感情线填写双人发动机：双方的面具、最怕被对方看见的东西、被对方吸引的具体点、此刻不能靠近的理由和想靠近的理由。多线项目还要写清每条线的独立目标与情感功能。

本步骤最低交付：主角、反派和关键配角的人物发动机——包括现实处境卡、心理发动机（Ghost/Lie/Flaw/Want/Need）、单一主导性人格特质、反派卡、主要配角卡，若有感情线则包括双人发动机，全剧核心戏剧动作，以及情绪内核的明确表述。人物发动机落地为具体行为时，使用 `references/core-methodology.md` 第 3 节的 XY 轴（内心执念只做推导依据，正文只写外化的向上/向下行为），不要把执念直接写成独白或旁白；关键剧情设计后做一次换人测试，剧情换成剧中任意其他人物走向不变的场次要重写。

**步骤 2 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；未收到 `[通过]`，不得开始步骤 3。

### 3. 搭建全剧留存架构

先回答 `references/review-checklist.md` 的九问，再把答案转化为因果大纲。不要把九问答案机械展示给用户，除非用户要求过程或审核报告。

用 `references/sequence-screenwriting.md` 把全剧拆成若干“小电影”：每个序列都要有局部目标、升级阻碍、局部结果和下一问题。

让各序列围绕同一情绪内核做不同变奏：更换冲突场域、关系对象、角色策略、信息差、胜负结果或付出代价。不要连续用同一种误会、打脸、背叛或救援重复表达同一种情绪。

若有感情线，在序列规划中同步标出每条线的亲密度升降节点（见 `references/romance-tension.md` 第 5 节），使中段每 5–8 集至少有一次关系升级或降级，避免感情线只靠斗嘴、吃醋和倒追重复。

按项目实际集数设计付费卡点链：

```text
开篇承诺 → 免费窗口内兑现第一次价值 → 卡点 1 扩大问题
→ 中段规则/关系升级 → 卡点 2 重定义问题
→ 后段选择与总爆发 → 卡点 3 汇合并回收前两卡
```

让卡点因果相连。删除中间卡点后若主线仍完全成立，说明卡点只是孤立刺激，需要重做。

本步骤最低交付：全剧因果骨架、序列划分、情绪变奏和相互递进的付费卡点链。

**步骤 3 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；未收到 `[通过]`，不得开始步骤 4。

### 4. 规划分集

为每集先填写内部单集卡：

```text
本集观看问题：
主角本集目标：
失败代价 / 为什么必须现在行动：
最大阻碍与中段升级：
本集新增信息或价值变化：
本集有效信息单元：
关键交锋双方目标 / 筹码 / 伤口：
核心场景机制：现实任务 / 公开体面 / 隐瞒试探 / 被迫合作 / 物件争夺 / 离开挽留 / 第三人误读 / 其他
主要人物各自不能直说的话：
本集关键情绪转向：从____到____
策略或权力换位：
感情线（本集有感情戏时填）：对象 / 亲密等级 前→后 / 推 / 拉 / 可拍表现 / 强势方软肋外显 / 物件状态
最高反转等级：R0 / R1 / R2 / R3 / R4
本集对核心情绪的功能：建立 / 否定 / 加深 / 暂时满足 / 污染 / 反转 / 最终证明
阶段性回答：
集末新问题 / 决定 / 危险：
下一集第一场启动动作：
预计时长：
外部情节节奏：松 / 中 / 紧
内部情感节奏：轻 / 中 / 重
```

遵守以下标准：

- 让开场窗口与单集时长匹配；短至 60–90 秒的集数通常要在前 1–3 秒出现异常、目标或冲突，更长集数也不得先做无压力背景说明。
- 让每集有阶段性回报，不用任意反转代替回报。
- 让集末产生明确向前拉力：未完成动作、不可逆决定、期限、揭示、关系变化或更大危险均可；不要强行制造与本集无关的事故。
- 让相邻集在外部强度与内部情感上有变化，避免连续重复同一种“虐、爽、吵、打脸”。
- 让相邻核心场景至少更换场域、场景机制、胜负方式或情绪落点中的一项；不要连续依赖站着对骂、突然闯入、偷听或亮身份。
- 高强度项目按 `references/dialogue-conflict-density.md` 配置有效信息单元、权力换位和反转等级；反转出现后必须改变角色行动。
- 感情线不得连续多集只有撒娇、斗嘴、吃醋或倒追同一种形态；中段每 5–8 集至少一次亲密等级升降。

第一至第三集额外读取 `references/opening-episodes.md`。试稿项目额外读取 `references/pilot-30-episode-structure.md`，按用户或平台最新要求调整节点。

本步骤最低交付：逐集列出观看问题、核心行动、阻碍升级、阶段回答、集末拉力和下一集启动动作。

**步骤 4 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；未收到 `[通过]`，不得开始步骤 5。

### 5. 写场景和正文

每场先确认：视角角色、双方相反目标、各自筹码和伤口、阻碍、场景机制、各自不能直说的话、人物声纹、有效信息单元、情绪转向、权力换位、结果、价值变化、余震以及如何递交下一场。感情场（关系里程碑、暧昧、拉扯、和解、决裂）改用 `references/romance-tension.md` 第 13 节的写前卡，不套用双方相反目标、筹码和权力换位；不用有效对白率、双功能对白率或反转等级衡量。详细场景卡见 `references/core-methodology.md`；对白与交锋强制读取 `references/dialogue-conflict-density.md`。用户反馈无聊、僵硬、情绪不真或“太 AI”时同时读取 `references/human-dialogue-emotional-rhythm.md`。

执行以下写作规则：

- 只写可见、可听、可表演的外显动作；把“意识到、很痛苦、深爱”改成动作、停顿、距离、物件、声音和选择。
- 先列信息单元，再按场景性质选择节拍形状；5–8 拍交锋梯只用于需要完整谈判或正面攻防的场景，不得每场机械套用。
- 每轮交锋整体推进目标、信息、关系、筹码、理解或行动；多数实质对白至少承担一项功能，允许少量改变表演节奏或给下一击蓄力的短反应。
- 关键交锋的双功能对白比例只用于写后诊断，不作为写作配额；不得为了达标让人物说出不符合身份、体面、恐惧和口语习惯的话。
- 让“拉满”表现为攻击精准、筹码具体、期限明确和选择不可逆，不用全程吼叫、辱骂或感叹号代替烈度。
- 删除双方已知却专门解释给观众的信息；关键揭示必须在 1–3 拍内改变反应、策略或局势。
- 关键揭示先给人物一个可表演反应，再决定是否需要解释；高峰后保留一个会改变称呼、距离、习惯或下一步选择的余震。
- 为主要人物建立不同的句长、称呼、礼貌、回避和攻击方式；避免同款完整论证、对称金句、万能反问、全名复读和库存动作。
- 让文戏改变信息、关系或权力；让动作戏改变局势、资源或规则。
- 写感情场时先定表层任务和底层心意，再定推与拉；用称呼、距离、物件和身体反应泄露心意；系统提示、情报或玩笑不得在关系里程碑后立刻拆台；感情高点不用网络梗。详见 `references/romance-tension.md`。
- 让角色主动选择策略；被动主角也必须在压力下采取可见行动。
- 使用 `references/script-format.md` 的场次、动作、台词与情绪排版。
- 每集钩子由末场最后 1–2 行完成，停在不可逆动作、揭示或关系反转上，并在集末加 `【集末钩子】` 标签行；开场第一个动作或第一句台词就抛出冲突；多集正文逐集完成，不得遗漏。
- 动作行 `△` 只写可见、可听的画面，一行一个动作节拍或信息；情绪写在台词括号里，用强而具体的情绪词；并遵守 `references/script-format.md` 第 3、4 节。

本步骤最低交付：按本轮约定集数或批次提交完整可拍正文；每集以钩子收尾；同时报告每集字数、场景数和台词字数（含旁白），并与用户或平台给定的体量标准对照（未给定时按默认 500–700 字、不超过 3 场、台词不超过 300 字写明假设），偏薄时补实质冲突，不用环境描写注水。

**步骤 5 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；未收到 `[通过]`，不得开始步骤 6。

### 6. 管理情绪、对白与关系

读取 `references/pacing-emotion.md`、`references/dialogue-conflict-density.md` 和 `references/human-dialogue-emotional-rhythm.md`。同时管理：

- 外部轨：事件密度、冲突和信息强度；
- 内部轨：关系变化和情绪重量。
- 交锋轨：有效信息、策略反制、筹码换位、情绪烈度和反转等级。
- 人声轨：主要人物的称呼、句长、礼貌、回避、攻击方式和压力下语言破绽。
- 场景活性：冲突机制、现实任务、物件、第三方和胜负方式是否与相邻场次变化。

若 CP 线是核心卖点，让双方在前段尽早产生有后果的互动，并在每次关键对手戏中改变关系；不强制所有题材都写成“双强”，但禁止一方长期只是奖品、工具或缺席的设定对象。感情线弱或用户反馈“没感觉”时，读取 `references/romance-tension.md`，并在校准报告中增加：各感情线亲密等级曲线、推拉次数、强势方软肋外显、独白占比、物件回收状态、系统或情节对高点的打断位置。

让虐点产生代价，让爽点来自行动与因果回收。不要按固定场数机械插入反转；在观众预期稳定前建立，在预期失效前升级。

保持全剧情绪内核稳定，让单集情绪功能持续变化。例如同样表达“女主从不被选择”：第一集可以是丈夫公开忽视，下一次变奏应改成母亲以保护为名替她决定，再下一次让事业伙伴在利益面前放弃她，最终让女主先选择自己。情绪相同，剧情机制不能相同。

本步骤必须作为用户可见交付，输出情绪、对白与关系校准结果：每集体量（字数、场景数、台词字数）与目标的差距、外部/内部双轨节奏、有效对白率、双功能对白率、有效信息单元、权力变化次数、最高反转等级、核心关系变化、重复桥段、虐爽因果，以及需要调整的具体位置和修订内容。不得只在内部检查。

报告中的百分比是诊断，不是质量本身。还必须输出：主要人物声纹是否可区分、AI 腔位置、缺失的潜台词/反应拍/余震、重复的场景机制，以及至少一处完成自然化改写的具体位置。

**步骤 6 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；未收到 `[通过]`，不得开始步骤 7。

### 7. 维护连续性

多集项目读取 `references/continuity-management.md`，持续更新：

- 角色物理、情感、关系、目标和知情状态；
- 主线、感情线、Running Subplot 和暗线进度；
- 伏笔的埋入、提醒与回收；
- 世界规则与已公开信息；
- 弧光预算和下一集必须延续的事项。

每完成一个序列或 3–5 集生成一次检查点；写完一批次或准备跨对话时输出可保存的检查点。

本步骤必须作为用户可见交付，输出连续性检查点：角色状态、关系与知情变化、各故事线进度、伏笔状态、世界规则、已确认内容和后续必须延续事项。不得只在内部维护。

**步骤 7 强制确认门**：提交上述结果后，立即输出固定三行确认口令并停止；步骤 7 收到 `[通过]` 后，完整创作流程才算完成；若用户另行要求终审，再进入终审路径。

## 执行终审

不要只给“节奏慢”“人设不够立体”等印象评价。按五个基础层诊断，再按需加层（见下方“按需加层”）：

1. **项目层**：概念承诺、主角目标、受众情绪、卡点链是否成立；
2. **序列层**：局部目标、阻碍升级、中点换挡和因果递交是否成立；
3. **单集层**：观看问题、阶段性回答、信息升级和集末拉力是否成立；
4. **场景层**：双方争夺、人物策略、价值变化、可拍摄性和时长是否成立；
5. **人声与对白层**：逐轮检查有效信息、反制、筹码、伤口、选择、行动后果、声纹差异、潜台词、反应拍、余震、AI 腔和反转等级；感情场不计入有效对白率、双功能对白率和反转等级，改在感情线层诊断。

**按需加层**：

- **人物层**（用户反馈人物扁平、像工具人，或整批正文终审时）：现实处境卡、主导性人格特质是否真的限制了选择、换人测试、反派独立行动路线、配角卡、人物闭环是否缺环，读取 `references/core-methodology.md` 第 3 节和 `references/review-checklist.md`；
- **感情线层**（感情线是卖点或用户反馈感情戏弱时）：各线亲密等级升降、推拉与代价、强势方软肋外显、独白与动作是否重复、高点是否被打断、物件回收、多线转变机制是否重复，读取 `references/romance-tension.md`；
- **文本质量与原创层**（交付前或用户要求自检时）：文笔与口水、重复对话标签、逻辑与法律严谨、冗余与环境描写、情感档位与结局承诺、导语与衔接是否套用原作模板，读取 `references/text-quality-originality-check.md`；
- **对抗式审稿**（用户要求审稿，或一批正文冻结前）：读取 `references/red-team-review.md`。

读取 `references/review-checklist.md` 和 `references/dialogue-conflict-density.md`；无聊、僵硬、同声或 AI 腔问题再读取 `references/human-dialogue-emotional-rhythm.md`。对每个问题给出：**位置 → 问题 → 造成的影响 → 修改动作 → 必要时给出短示例**。先修概念和结构，再修场景机制、争夺与信息顺序，最后修人物声纹和句子自然度；不要只把词写得更狠。

## 输出纪律

- 每次只交付当前用户可见步骤的结果，并以“逐步确认机制”的三行确认口令收尾；未获确认不得进入下一步。
- 方案之间必须有结构差异，不得只换名字、职业或表面设定。
- 仅在立项、分集大纲或用户明确要求的时长分析中标注预计时长；剧本正文严格使用 `references/script-format.md` 的场次行，禁止追加逐场秒数。标注假设、付费节点和平台规则来源；无法确认的规则写成“待核实”，不要伪装成确定事实。
- 不展示冗长的内部检查过程；用户要求自检或终审报告时再展开。
- 不模仿具体作品的受保护表达，不复刻原作台词与独特情节。IP 项目先确认授权范围，并兼顾新观众入口。
- 案例参考只迁移结构功能和密度标准；不得整条照搬六集事件链。使用 `references/benchmark-case-dialogue.md` 时至少更换现实刚需、对手筹码、关系性质和身份连接方式。
- 使用《疯狂主妇的秘密》参考时只迁移“处境先行、生活物件、短反应、动作接棒、关系位置和多形态集末”等机制；不得复制人物、病症、家庭关系链、台词或独特桥段。

## 交付前自检

- [ ] 一句话能说清主角、目标、阻碍和代价。
- [ ] 开场已经进入压力状态，不是背景说明。
- [ ] 阻碍至少两次异质升级，角色没有靠降智维持误会。
- [ ] 高潮是关键选择的行动化，不只是更大的场面。
- [ ] 每集解决一个局部问题并制造更重要的新问题。
- [ ] 每场改变信息、关系、权力、风险、资源、计划或自我认识中的至少一项。
- [ ] 每场都能说清双方相反目标、各自筹码、权力换位和不可逆结果；感情场按 `romance-tension.md` 第 13 节单独诊断，不套用本条。
- [ ] 高强度正文已用有效对白率和双功能对白率做写后诊断，没有连续空转；未为达标牺牲自然口语和人物声纹；感情场不纳入这两项统计。
- [ ] 关键揭示在 1–3 拍内产生行动后果；关键场至少达到 R2，付费卡点或强集末优先达到 R3。
- [ ] 心理与主题都有可拍表现；台词口语化、有潜台词、能区分人声，并以具体筹码和选择制造烈度。
- [ ] 主要人物没有同款完整论证、对称金句、万能反问和库存动作；每人只说此刻敢说、愿说和来得及说的部分。
- [ ] 关键揭示后有可表演反应，强情绪高点后有改变称呼、距离、习惯或选择的余震。
- [ ] 相邻核心场景至少改变场域、场景机制、胜负方式或情绪落点中的一项，没有连续站着对骂。
- [ ] 已按 `references/text-quality-originality-check.md` 完成文笔、对话标签、逻辑与法律、冗余与环境描写、导语原创检查；情感标签与结局承诺一致；
- [ ] 本序列的主驱动清楚；案件外壳（监控、录音、字条、对质、设局破局）没有占据主要篇幅，也没有把感情线、家庭线连续搁置；
- [ ] 每条感情线有清楚的推与拉、亲密等级升降和可拍表现；强势方至少露出一次软肋，好意不全是有奖励的；
- [ ] 内心独白没有复述台词与动作已表达的心意；感情高点后没有被系统、情报或玩笑立刻拆台；情书、礼物类物件的内容有展示、有回收。
- [ ] 外部节奏与内部情感有波浪，不长期双高或双低。
- [ ] 主要剧情都在从不同角度推进同一情绪内核，没有情绪跑题或同类桥段重复。
- [ ] 伏笔有回收，角色与信息状态连续。
- [ ] 输出格式、单集时长与平台参数符合本项目，而非机械套用默认值。
- [ ] 场次行仅含场次编号、内外景与日夜、地点，人物另起 `人物：` 行，没有“约 XX 秒”等逐场时长。
- [ ] 场景、动作、台词、情绪四要素齐备：`△` 动作行只写可见可听内容；台词行为“角色名（情绪）：台词”并单独成行；镜头提示用 `——`。
- [ ] 开场第一个动作或第一句台词即抛出冲突；每集末场最后 1–2 行完成钩子，并与已戏剧化呈现的悬念一致。
- [ ] 第 1—7 步均作为独立用户可见交付；当前步骤末尾完整包含 `[通过]`、`[修改]`、`[自检]` 三行确认口令，并已停下等待选择。
