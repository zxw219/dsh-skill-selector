# 交付结构与检查

建议结构（名字按项目变化）：

```text
项目_LUT/
  LUT/
    ProjectLook_Rec709_33.cube
    ProjectLook_Rec709_65.cube
  预览/
    参考_原片_效果_三栏.jpg
    目标视频_LUT效果.mp4        # 目标为视频时完整预览
    图片01_LUT效果.png          # 目标为图片时逐张输出
  使用说明.md
  制作参数/
    recipe.json
    grade_engine.py
    media_tools.py
    validation_33.json
    validation_65.json
    source_metadata.json
    reproduction.md
  manifest.sha256              # 实际名称以 package 工具输出为准
  项目_LUT_完整交付包.zip
  _work/                       # 默认不整目录打包
```

从技能目录复制实际使用的脚本，配方和说明使用相对包内路径；重现步骤中的原素材用“请指定原素材路径”，不宣称 ZIP 自带未打包的源视频。记录需要的依赖/版本及任何预转换步骤。源元数据只保留重现有用的信息，避免无关机器隐私。

## 三栏图

- 左列参考，中央原片，右列最终实渲；每行中右同图、同构图、同尺寸。
- 顶部标出项目名、LUT 强度、工作色彩空间。列标题不能靠文件名让人猜。
- 参考和目标若不是同场景，明确“参考仅用于色彩对照，非同场景”。不将其画面内容差异算作 LUT 效果。
- 参考竖屏、目标横屏时等比留边，保留完整画幅。文字置于图外，不覆盖脸、灰墙、高光等比较对象。
- 多张目标按照明暗/肤色代表性选择，多页时每页保持列次序；单张目标可只交一行。
- 对比的右列必须由交付那份实际 cube 渲染，不能用图像生成、另一组编辑参数或陈旧候选结果替代。

## 中文使用说明必须说清

1. 优先导入哪份、经过测试的强度。33³/65³ 是同风格不同密度，二选一，不叠加。
2. LUT 对应输入空间。Log/HDR 输入转换顺序；源标记缺失时的假设。
3. 首次对照时关闭原滤镜和自动调色；复用不同素材先校正曝光/白平衡。按用户软件给出简短导入路径，未操作该软件时如实说明。
4. 预览范围、尺寸/帧率、音频、转码位深。示例画面精确匹配的是哪个版本和强度。
5. 无配对参考时这是风格近似；LUT 无法保存颗粒、光晕、局部补光等空间效果。
6. 若某项未完成，准确说明缺项，不把部分包称完整。

## 交付前门槛

- 每份 cube 的大小声明、行数、数值范围、有限值、R-fastest 排序通过实际加载验证；报告哈希对应当前文件。
- 配方变化后重建两种密度，重渲对应预览和对比，报告不残留旧哈希。
- 实际查看代表帧，复核黑位、脸部、亮部和主要饱和色；视频全片解码检查无错误，核对画幅/节奏/音轨和标签。脚本不能替代审美评价。
- ZIP 显式包含交付文件，校验可读和 SHA-256；不包含自己，不递归误收源媒体、下载缓存或临时失败文件。
- 用户要的主 LUT、三栏图、目标结果、说明和完整 ZIP 都有有效路径。局部示例测试不等于全片完成。

可以用 `media_tools.py package`；按 `media-tools.md` 的实际 CLI 传入明确路径。若用户只要 LUT 文件而拒绝附加预览，尊重范围，不为了满足默认清单强制新增输出。
