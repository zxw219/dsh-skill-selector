# 交付检查与成片诊断

检查的目标是保护用户锁定内容和关键因果，不是把所有电影惯例变成硬规则。用户有意选择的跳切、越轴、静止、长镜、无音乐或强音乐均可成立，只需让选择在成片中可读。

## 一、交付门禁

正式提示词交付前确认：

- 片段中心结果清楚，开头承诺在片尾兑现、失败或发生明确转折；
- 用户锁定的人物、场景、原台词、事件、产品或道具变化和结尾全部出现；
- 每项采用素材职责明确，未采用素材没有被调用，标记使用当前入口真实语法；
- 时间轴从0秒连续覆盖至总时长，无空档、倒序和无意重叠；
- 对白、完整动作、反应、摄影机移动和结果有足够执行时间；
- 关键动作包含触发、起点、作用对象、接触或避开、反馈和终点；
- 摄影机能看清决定性证据，切镜或运镜确实增加信息；
- 多人位置、路线、视线、持物、伤势、光源和声场连续；
- 对白的说话人、口型或画外声源、身体状态和听者反应明确；
- 特效与环境共享遮挡、受光、接触、反射、声音或残留；
- 连续生成没有重演前段，编辑任务没有破坏保持区域；
- 正式稿不含解释、占位符、虚构素材编号或需要用户手工拼接的残段；
- 当前入口有字符上限时已精确计数，并留出必要修改余量。

若一个关键事件、素材身份或编辑范围仍有两种会改变结果的解释，先向用户确认。

## 二、成片证据卡

把“效果不好”改写为：

`时间段｜画面区域｜对象｜实际出现｜期望出现｜已成功内容｜直接证据`

例如：

`6.3–7.1秒｜画面左侧｜持刀人物右手｜刀在切镜后消失｜应继续握住并指向门口｜脸、服装和机位正确｜前镜末帧可见刀仍在右手。`

一次失败能证明症状，不一定证明唯一原因。不要仅凭结果猜测平台能力或模型内部机制。

## 三、诊断顺序

1. 正式稿是否明确写出必须发生的动作和结果；
2. 素材是否争夺同一身份、动作、空间、镜头或声音；
3. 当前时长是否足够完成事件、反应和镜尾收束；
4. 摄影机是否让关键证据太小、被遮挡或发生在切镜之外；
5. 动作是否缺少支撑、接触、受力、对象反馈或结束状态；
6. 连续生成是否缺少前段镜尾状态或重复了参考音轨；
7. 编辑范围是否过宽，或把必要的阴影、遮挡、反射和声音一起冻结；
8. 提示词是否被设备名、同义风格词和泛化禁止项挤占；
9. 当前入口是否真正支持所写的素材引用和编辑方式。

按顺序找到最早断裂处。后面的视觉症状经常只是前面因果缺口的结果。

## 四、症状与修复方向

| 可观察症状 | 优先检查 | 最小修复 |
|---|---|---|
| 人物或产品漂移 | 身份来源不唯一、其他素材越权 | 指定唯一主控素材，排除其他素材的身份影响 |
| 动作发软或像摆拍 | 缺支撑、接触和对象反馈 | 补起点、作用点、反作用、终点与环境证据 |
| 快动作变成乱切 | 单位时间事件过多、机位也过度运动 | 减少动作节点，用宽镜保路线、近镜保接触 |
| 多人场面互相抢动作 | 没有主行动者和反应先后 | 分时段指定行动者、承受者和背景维持者 |
| 镜头多但看不懂 | 切镜没有新信息或空间重建 | 删除重复角度，给出路线、地标和明确结果 |
| 台词说错人或乱口型 | 声源、画面主体和时段未绑定 | 同步写说话人、原文、口型、听者及反应 |
| 情绪突跳或切镜复位 | 缺刺激、策略变化和余波 | 从关键词/事件开始反应，并把呼吸、视线带入后镜 |
| 特效像贴纸 | 缺遮挡、受光、接触和残留 | 让特效改变人物、环境、声音或后续状态 |
| 后续片段像重播 | 开头复述前段高潮 | 只继承镜尾，从下一行为开始并排除原声复读 |
| 局部编辑带动全片 | 保持区域与直接牵连不清 | 缩小目标，列出允许变化、伴随变化和冻结内容 |
| 提示词过长仍漏事件 | 重复形容和设备参数过多 | 先保身份、事件、动作结果、对白、编辑范围和镜尾 |

## 五、返修输出

用户要求修改时：

1. 用一至三句说明可观察问题和最可能的控制缺口；
2. 列出本轮保持不变的成功项；
3. 只改故障项和它的直接牵连；
4. 交付一份完整替换提示词；
5. 若仍存在不确定原因，提出一个可区分原因的测试变量。

不要同时大改人物、动作、镜头、光线和声音来试运气。一次改变一个主变量，才能知道成片变化来自哪里。

## 六、对比测试

需要判断两个写法时，保持相同的素材、入口、时长、画幅、随机条件和核心事件，只改变一个控制层，例如：

- 动作是否加入接触和反作用；
- 多素材是否改为唯一身份来源；
- 镜头是否从近景改为能看清路线的中远景；
- 连续段是否删除上一段高潮复述；
- 负面约束是否缩减为三项最高风险。

评价成片时使用可观察指标：身份稳定、事件完成、动作可读、空间连续、对白归属、素材服从、镜尾准确。不要只比较“更有电影感”。

## 七、自动检查

`scripts/validate_prompt.py` 检查六栏结构、【事件脚本】的时间轴连续性、时长、字符上限、素材标记和占位符，以及【全局补充】是否单列 `完全忽略@黑屏素材`。例如：

```bash
python scripts/validate_prompt.py prompt.txt --duration 14 --max-chars 8000 --require-token @图1 --forbid-token TODO
```

也可以把当前入口条件保存为 UTF-8 JSON：

```json
{
  "duration": 14,
  "max_chars": 8000,
  "required_tokens": ["@图1", "@图2"],
  "forbidden_tokens": ["TODO"]
}
```

再运行：

```bash
python scripts/validate_prompt.py prompt.txt --profile profile.json
```

自动检查只能发现形式问题，不能证明动作可拍、素材匹配或剧情完整。脚本通过后仍需做一次人工因果检查。
