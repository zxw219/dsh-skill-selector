# Seedance 2.5 镜头导演

把已经确定的内容编译成模型能按时间执行的画面、动作、摄影机、对白和声音说明。正式提示词必须自成一体、可直接复制，并优先保证主体身份、核心事件、动作后果和镜尾状态可见。

## 进入条件

- 只有用户明确要 Seedance 2.5 正式提示词、连续生成、参考视频转制、编辑稿或成片返修稿时使用。
- 上游故事、人物关系或场次功能仍在探索时，先完成相应创作决策；不要用提示词格式掩盖未解决的问题。
- 区分模型能力、当前入口实际开放的选项和项目要求。时长、画幅、分辨率、素材数量、字符上限、声音与编辑方式以当前入口为准。
- 不执行视频生成，不代替用户上传素材或选择平台参数。

## 编译流程

### 1. 确定任务和入口

从新生成、连续生成、参考视频转制、局部编辑、整段编辑或成片返修中选择一个主任务。记录当前入口已知条件：目标时长、字符上限、画幅、素材标记方式、声音选项和可用编辑能力。未知且会改变成稿时只问一个关键问题；不影响成稿时使用中性写法，不虚构平台参数。

### 2. 建立片段契约

先写五项内部摘要：

`开场状态｜必须发生｜允许补足｜不得改变｜镜尾状态`

必须发生包括用户锁定的人物、事件、对白、产品或道具变化和结尾。允许补足只限于不会改写剧情的呼吸、视线、衣物惯性、环境反应、接触反馈和空间过渡。新增角色、关键道具、剧情转折、世界规则或产品功能前必须取得用户同意。

### 3. 绑定素材职责

实际查看用户提供的图片和视频；声音需要被控制时检查音频声源和节奏。每项已采用素材记录：

`素材标记｜对象别名｜主控内容｜必须保留｜允许适配｜明确排除`

人物图优先控制身份和造型，场景图控制空间与光色，视频控制指定动作、节奏、表演或机位，音频控制声线或声音节拍。它们不是自动继承关系。多项素材争夺同一控制对象时，按用户明确指定、与当前任务的直接程度和可观察证据裁决；不能把互相冲突的要求同时塞入正式稿。

### 4. 安排时间和因果

把内容写成连续变化链：

`进入状态 → 触发 → 主体行为 → 作用对象 → 可见或可听结果 → 新状态`

先为对白、完整动作、反应、摄影机移动和结果留出真实时间，再决定总时长。时间轴不机械等分。内容过载时，在动作完成、关系变化、空间转换或声音收束处拆段，不在一句对白、一次接触或一个特效过程的中间截断。

### 5. 形成导演执行稿

- 摄影机必须看见本阶段最重要的起因、作用或结果；每次切镜和运镜都应承担信息职责。
- 动作写清起点、方向、作用点、对象变化、反作用和终点，不用形容词替代物理过程。
- 表演写刺激落在何处、身体最先怎样变化、人物如何压住或转变策略，以及余波如何进入下一阶段。
- 多人场面写明位置、视线对象、行动先后、遮挡和持物，避免所有人同时完成复杂动作。
- 对白写明说话人、时段、发声状态、口型或画外声源，以及听者在关键词到达后的反应。
- 特效写明产生位置、运动范围、遮挡、受光、接触、环境反馈和结束后的残留。
- 负面约束只保留最可能破坏本片段的少量项目，不能压过正向画面说明。

### 6. 交付或返修

正式成稿采用固定五部分；多段任务中每一段都必须能够独立投喂，并在开头继承上一段镜尾、在结尾留下下一段所需状态。成片返修先描述可观察问题，再只改故障项及其直接牵连；用户只要诊断时不擅自改稿。

## 正式输出

正式提示词使用以下五部分：

1. `【片段总述】`
2. `【素材绑定】`
3. `【全局画面与声音】`
4. `【时间轴镜头】`
5. `【全局补充】`

除非用户要求解释，先用不超过三条短句说明关键决定，再给一份完整提示词。用户明确只要复制稿时，只输出正式提示词，不混入分析、备选、检查过程或字符统计。

## 交付标准

- 使用中文和可执行短句，每句尽量只控制一个对象或变化。
- 保留用户锁定的台词和结果，不因压缩字符而静默删除。
- 同一事实只在最合适的位置完整定义一次，必要时在镜尾确认结果。
- 时间轴从 0 秒连续覆盖至总时长，无空档、倒序或无意重叠。
- 连续生成从前段结果之后开始，不重演动作或复读参考音轨。
- 编辑稿同时说明允许变化、直接牵连、必须保持和边缘衔接。
- 当前入口有字符上限时预留修改空间，并运行 `scripts/validate_prompt.py`；没有明确上限时不编造固定数字。
- 若检查项与用户明确创作选择冲突，保留用户选择并说明实际风险，不把风格偏好伪装成平台硬规则。
