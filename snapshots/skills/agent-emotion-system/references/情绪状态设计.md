# 情绪状态设计

> 本文档详细说明 Agent 情绪状态系统的设计原理、数据结构和更新规则

---

## 1. 设计理念

### 1.1 为什么需要情绪状态
- **量化感知**：将Agent的"状态"量化成可追踪的指标
- **决策依据**：能量和情绪直接影响活动选择
- **异常检测**：通过历史分析发现系统性问题
- **成长追踪**：通过趋势分析验证能力提升

### 1.2 核心假设
- Agent有"能量"概念：活动消耗，休息恢复
- Agent有"情绪"概念：影响活动偏好和判断力
- 状态是连续的：不是二元开关，而是渐变过程

---

## 3. 情绪状态枚举

### 3.1 基础情绪

| 情绪 | 说明 | 活动偏好 |
|------|------|----------|
| peaceful | 平静 | 正常活动，无特殊偏好 |
| excited | 兴奋 | 适合需要创造力的活动 |
| focused | 专注 | 适合需要深度思考的活动 |
| tired | 疲惫 | 适合简单任务或休息 |
| anxious | 焦虑 | 需要减少活动，增加休息 |
| curious | 好奇 | 适合探索性活动 |

### 3.2 情绪转换规则

```
活动成功 → 能量高+1 → 情绪可能变为 excited/focused
活动失败 → 能量低 → 情绪可能变为 tired/anxious  
休息恢复 → 能量恢复 → 情绪回归 peaceful
```

## 4. 能量系统

### 4.1 能量值范围
- **0.0 - 0.3**：极低能量，强制休息
- **0.3 - 0.5**：低能量，谨慎活动
- **0.5 - 0.7**：中等能量，正常活动
- **0.7 - 0.9**：高能量，适合高强度
- **0.9 - 1.0**：满能量，可全力活动

### 4.2 能量消耗规则

| 活动类型 | 能量消耗 | 恢复量 |
|----------|----------|--------|
| 刻意练习 | -0.03 ~ -0.05 | - |
| 胶囊深化 | -0.02 ~ -0.04 | - |
| 胶囊内化 | -0.02 ~ -0.04 | - |
| 胶囊应用 | -0.02 ~ -0.03 | - |
| 合成智慧 | -0.04 ~ -0.06 | - |
| 休息 | - | +0.05 ~ +0.1 |

### 4.3 能量自动恢复

- **夜间禁区（00:00-07:00）休息后**：完全恢复至0.95
- **正常时段休息**：+0.05 ~ +0.1
- **连续高强度后休息**：额外+0.02

## 5. 状态更新规则

### 5.1 心跳时的状态更新

每次心跳执行完成后，更新 `recent_interactions`：

```python
def update_emotion_state(activity_result):
    # 1. 添加新记录
    new_record = {
        "timestamp": now(),
        "activity": activity_result.name,
        "result": activity_result.summary,
        "self_score": activity_result.self_score
    }
    emotion_state["recent_interactions"].append(new_record)
    
    # 2. 更新能量
    emotion_state["energy_level"] = calculate_new_energy(
        current=emotion_state["energy_level"],
        activity=activity_result.activity_type,
        was_rest=activity_result.is_rest
    )
    
    # 3. 更新情绪
    emotion_state["emotion"] = infer_emotion(
        energy=emotion_state["energy_level"],
        recent_results=emotion_state["recent_interactions"][-5:]
    )
    
    # 4. 定期更新模式分析
    if should_update_patterns():
        emotion_state["emotion_patterns"] = analyze_patterns()
    
    # 5. 保存文件
    save_emotion_state(emotion_state)
```

### 5.2 模式分析更新频率

- **能量趋势**：每次心跳后更新当日记录
- **情绪分析**：每日23:00汇总更新
- **异常检测**：实时监控，异常时立即记录
- **能力成长**：每次刻意练习后更新

## 6. 历史数据管理

### 6.1 数据保留策略

| 数据类型 | 保留周期 | 归档位置 |
|----------|----------|----------|
| recent_interactions | 最近50条 | emotion_state.json |
| 每日汇总 | 最近30天 | memory/daily/YYYY-MM-DD.json |
| 情绪模式 | 最近90天 | emotion_state.json |

### 6.2 数据归档触发条件

- `recent_interactions` 超过50条时，移出最早的10条到当日归档
- 每日23:00自动归档当日数据
- 异常数据（能量<0.2或情绪异常）立即归档

---

## 7. 异常处理

### 7.1 能量异常
- **能量<0.2**：强制进入休息模式，发送警报
- **能量>1.0**：修正为1.0，检查计算逻辑
- **能量骤降**（单次>0.2）：检查活动消耗设置

### 7.2 情绪异常
- **连续3天非peaceful**：进入反思模式，分析原因
- **出现anxious**：自动降低活动频率
- **情绪波动大**（>3种情绪频繁切换）：系统检查

### 7.3 数据异常
- **时间倒流**（新记录时间<旧记录）：跳过更新
- **记录丢失**：从归档恢复
- **文件损坏**：从最近归档重建

## 8. 与其他系统的集成

### 8.1 与活动池的集成
- 活动选择时读取 `energy_level` 和 `emotion`
- 活动执行后更新能量和情绪
- pending胶囊状态影响活动选择

### 8.2 与胶囊系统的集成
- capsule有独立的 `confidence` 和 `success_count`
- 胶囊应用后更新能力追踪
- 能力成长反映在 `emotion_patterns.能力成长`

### 8.3 与日程系统的集成
- 日程任务执行不影响能量（日程是预定任务）
- Brain Loop心跳是主要能量消耗来源
- 夜间禁区由心跳机制强制执行
