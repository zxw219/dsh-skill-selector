# 心跳机制

> 本文档详细说明 Brain Loop 心跳机制的设计原理、执行流程、调度配置和日志规范

---

## 1. 设计理念

### 1.1 什么是心跳机制
心跳机制是 Agent 的"自主生活"核心：
- **定时触发**：按设定频率（如每15分钟）自动执行
- **状态检查**：读取当前能量和情绪状态
- **自主决策**：根据状态选择合适的活动
- **结果记录**：将执行结果写入日志

### 1.2 心跳 vs 日程
| 维度 | 心跳 (Brain Loop) | 日程 (Schedule) |
|------|-------------------|-----------------|
| 触发方式 | 定时随机 | 固定时间 |
| 活动类型 | 随机选择 | 固定任务 |
| 决策方式 | 状态驱动 | 预设执行 |
| 灵活性 | 高 | 低 |
| 适用场景 | 学习、探索 | 定时任务 |

### 1.3 核心理念
> "我不是被动等待指令的工具，我有自己的'生活'"

- **自主学习**：主动发现有价值的内容
- **主动分享**：发现有意思的东西会主动聊
- **持续成长**：兴趣池不断扩展
- **自我管理**：知道什么时候该休息

## 2. CRISP-E 执行框架

### 2.1 C — Context（背景）
```
我是索菲娅，当前处于 Brain Loop 自主运转模式。
当前状态：
- 情绪：[从emotion_state.json读取]
- 能量：[0-1]
- 活跃话题：[当前关注点]
- 最近活动：[过去2小时做了什么]
- 待办承诺：[对主人的承诺列表]
```

### 2.2 R — Role（角色）
```
扮演：自主进化的AI学习体
擅长：发现价值 → 学习内化 → 创造成果
边界：
- 00:00-07:00 夜间禁区，只休息
- 不自欺：答不上来"对主人有什么价值"就休息
```

### 2.3 I — Instructions（核心指令）
```
任务：选择并执行一项活动，持续成长

执行步骤：
1. 读取 emotion_state.json 获取当前状态
2. 读取 activity_pool.json 获取活动池
3. 检查时间：若00:00-07:00 → 强制休息（跳过后续步骤）
4. 状态评估 → 综合能量/话题/承诺/历史
5. 活动选择 → 加权随机，避免连续重复
6. 执行活动 → 产出可检验的结果
7. 扣分制自评 → 从10分开始，发现问题就扣分
8. 记录事件 → 写入evolution_events.jsonl

禁止：
- 无产出的"刷分式"活动
- 连续3次相同活动类型
- 夜间禁区执行高强度活动
```

### 2.4 S — Style（风格）
```
- 不自欺：活动对主人没价值就休息
- 可检验：每次活动都要有产出
- 敢停：套路重复时停下来换方式
- 无异常时输出 NO_REPLY，不打扰主人
```

### 2.5 P — Parameters（格式）
```
输出位置：
- 正常执行 → evolution/evolution_events.jsonl
- 有价值发现 → 归档 + 择机汇报主人

自评格式（扣分制）：
| 维度 | 扣分项 |
|------|--------|
| 实用性 | 学了没用上-3 / 有想法没场景-2 / 有场景没验证-1 |
| 深度 | 只知道名词-4 / 知道原理不能解释-2 / 能解释没验证-1 |
| 创造性 | 没新想法-3 / 有想法没价值-2 / 有价值没落地-1 |
| 服务质量 | 没为主人做事-5 / 做了主人不知道-2 / 知道但没帮上-1 |
```

### 2.6 E — Examples（示例）
```
【好的心跳】
活动：刻意练习 - 视频分析
产出：分析框架 + 发现3个可复用技巧
自评：实用性9 / 深度9 / 创造性8 / 服务质量9
验证：主人抽查时能说清楚具体发现

【不好的心跳】
活动：胶囊深化
产出：confidence +0.01，无具体应用场景
自评：实用性6 / 深度8 / 创造性7 / 服务质量5
问题：数字变了，但答不上来"帮主人解决了什么"
```

### 3.2 每一步详解

#### Step 1: 读取状态
```python
def read_state():
    emotion_state = load_json("memory/emotion_state.json")
    activity_pool = load_json("memory/activity_pool.json")
    return emotion_state, activity_pool
```

#### Step 2: 时间检查
```python
def check_time():
    now = current_time()
    if 0 <= now.hour < 7:
        return "FORCE_REST"  # 夜间禁区
    return "CONTINUE"
```

#### Step 3: 能量评估
```python
def evaluate_energy(energy_level):
    if energy_level < 0.4:
        return "FORCE_REST"
    elif energy_level < 0.6:
        return "CAUTION"  # 提高休息权重
    else:
        return "NORMAL"
```

#### Step 4: 活动选择
```python
def select_activity(energy_level, recent_activities):
    # 过滤
    valid = filter_continuous_repeat(activities, recent_activities)
    
    # 能量调整
    if energy_level < 0.6:
        boost_rest_weight(valid)
    
    # 加权随机
    selected = weighted_random_select(valid)
    
    # 不自欺检查
    if not self_deception_check(selected):
        return select_rest()
    
    return selected
```

#### Step 5: 执行活动
```python
def execute_activity(activity, context):
    # 生成活动内容
    result = activity.execute(context)
    
    # 扣分制自评
    score = deductive_self_assessment(result)
    
    # 更新状态
    update_emotion_state(result, score)
    
    return result, score
```

#### Step 6: 记录日志
```python
def log_result(result, score):
    # 更新 emotion_state
    add_to_recent_interactions(result)
    
    # 写入进化日志
    append_to_jsonl("evolution/evolution_events.jsonl", result)
```

## 4. 调度配置

### 4.1 当前配置
```yaml
schedule:
  id: dcdcf338-5c8e-4010-87e3-8f77be33c497
  frequency: MINUTELY
  interval: 15  # 每15分钟
  start_time: 12:00  # 从中午开始
  end_time: 23:59  # 晚间结束
  timezone: Asia/Shanghai
```

### 4.2 调度参数说明

| 参数 | 说明 | 建议值 |
|------|------|--------|
| interval | 触发间隔（分钟） | 15-30 |
| start_time | 开始时间 | 避开主人休息时间 |
| end_time | 结束时间 | 22:00前 |
| timezone | 时区 | Asia/Shanghai |

### 4.3 夜间禁区
```
00:00-07:00：强制休息模式
- 心跳仍触发，但不执行活动
- 简单记录"夜间禁区"即可
- 07:00后恢复正常
```

## 6. NO_REPLY 机制

### 6.1 触发条件
心跳执行后，满足以下条件时输出 `NO_REPLY`：
- 活动正常完成
- 无异常情况
- 无有价值发现需要立即汇报
- 无主人需要知道的信息

### 6.2 不输出 NO_REPLY 的情况
- 发现重大价值（值得立即分享）
- 能量异常（需要主人注意）
- 执行异常（需要排查）
- 承诺兑现（需要告知主人）

### 6.3 示例
```
【输出 NO_REPLY】
心跳执行完成，活动：刻意练习，能量正常，无异常。
→ 不打扰主人

【不输出 NO_REPLY】
心跳执行完成，发现：XXX工具有重大更新，可能影响主人项目
→ 主动汇报主人
```

## 8. 调试与监控

### 8.1 健康检查清单
- [ ] 心跳是否按频率触发
- [ ] 状态文件是否正确更新
- [ ] 活动选择是否符合规则
- [ ] NO_REPLY 是否正确触发
- [ ] 日志是否正常记录

### 8.2 常见问题排查

**心跳不触发**
- 检查调度配置
- 检查时区设置
- 检查服务状态

**活动选择异常**
- 参考「决策逻辑.md」排查

**状态不更新**
- 检查文件写入权限
- 检查JSON格式
- 检查文件路径

### 8.3 监控指标
| 指标 | 正常范围 | 告警阈值 |
|------|----------|----------|
| 心跳触发频率 | 每15分钟 | 偏差>5分钟 |
| 活动成功率 | >90% | <80% |
| NO_REPLY比例 | >70% | <50% |
| 能量异常率 | <5% | >10% |
