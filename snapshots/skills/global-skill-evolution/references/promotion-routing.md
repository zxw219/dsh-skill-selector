# Promotion Routing

Use this table after validation.

| Signal | Promote To |
|---|---|
| One skill has a local wording, structure, or guardrail problem | That skill |
| A recurring workflow is distinct and not owned cleanly anywhere | New skill |
| A reusable rule is validated across contexts | Capsule |
| A routing rule affects many skills | Orchestrator or global policy |
| A user-confirmed rule should survive future threads | Formal global docs |
| A one-off fix does not generalize | Nowhere beyond the local task |

## Promotion Rules

### Promote to a skill when

- execution steps must be repeatable;
- the behavior needs triggerable instructions;
- the workflow is broader than one capsule rule.

### Promote to a capsule when

- the lesson is reusable but smaller than a whole workflow;
- evidence and boundaries exist;
- it should feed multiple skills.

### Promote to global docs when

- the rule affects many future threads;
- it is a stable operating policy;
- losing it to thread compression would hurt future work.

### Keep local when

- the issue is project-specific;
- evidence is still thin;
- the fix may not generalize.
