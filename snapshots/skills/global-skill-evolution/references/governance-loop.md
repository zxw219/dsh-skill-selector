# Governance Loop

Use this loop for skill governance:

```text
discover -> diagnose -> synthesize -> validate -> ratchet -> propagate
```

## 1. Discover

Accept only concrete inputs:

- user correction;
- recurring failure fingerprint;
- validated success worth reusing;
- stale or duplicated skill logic;
- relevant external method worth adapting.

## 2. Diagnose

Reduce the issue to one main level:

- local wording/metadata;
- workflow structure;
- routing/orchestration;
- reusable rule;
- global policy.

Do not patch symptoms before naming the mechanism.

## 3. Synthesize

Use synthesis to:

- compress useful external ideas;
- merge overlapping rules;
- restructure a skill;
- extract the smallest reusable control.

Keep only what improves execution.

## 4. Validate

Before accepting a non-trivial change:

- compare old vs new;
- run a rubric pass;
- check for regression;
- validate files and scripts;
- use independent forward-testing when the stakes justify it.

## 5. Ratchet

Keep only changes that improve one or more of:

- trigger precision;
- execution reliability;
- scope clarity;
- guardrails;
- routing quality;
- long-term maintainability.

## 6. Propagate

Route the result to the smallest lasting layer:

- same skill;
- adjacent skill;
- capsule;
- orchestrator/global policy;
- formal long-term docs.

Thread summaries do not count as propagation.
